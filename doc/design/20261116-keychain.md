# Keychain

## 为什么要做？

塑料碗要保存的密钥越来越多，而且不都是 LLM Provider 的密钥：图片生成、联网搜索、MCP、Telegram 各自都需要。有的服务商压根不提供常规的 LLM API，只提供图片生成。

密钥的存放已经统一了：配置里只写引用，明文在配置文件旁边的 `key.json`（key jar）。但它距离 keychain 还差一截，差的是**每把密钥没有稳定的身份**：

- 面板和 `configure` 录入的密钥，条目名是随机串，人认不出来。
- 换密钥必须新建条目、换一个新名字。因为热应用只看引用有没有变，不看值有没有变。
- 所以同一把密钥没法被多处共用。同一把 OpenRouter 密钥给对话模型和图片生成各用一次，就要录两遍，轮换也要改两处。
- 图片配置为了让多个模型共用一把密钥，已经在自己的段里另起了一层「凭据名」。这是同一个问题的局部解法。
- 没有任何地方能看到「现在存了哪些密钥、各自被谁使用」。

另外，现在每次写入配置都会自动删除不再被引用的条目：

- 「先存一把暂时没用上的密钥」因此无法成立。
- 存在误删风险：图片配置段结构不合法时会被整段忽略，此时任何一次配置写入（包括成员自助的忽略命令）都可能把图片用的密钥删掉。这一条是阅读代码得出的，尚未复现。

## 希望实现什么？

- 每把密钥有一个稳定、可读的名字。用户只需要记住一句话：**密钥有名字，用的地方指向名字**。
- 同一把密钥可以被多处使用，轮换时只改一处。
- 管理员能在面板里看到所有密钥和它们的使用处，并一键清理没人用的密钥。
- 不加重用户的心智负担：填密钥的方式和现在一样，不要求先去别处建条目。
- 用环境变量或外部命令提供密钥的高级用户，配置不需要任何改动。

## 打算怎么做？

### 把 key jar 升级成 keychain

- 不新增配置概念。keychain 就是升级后的 key jar，配置里的引用写法不变。
- 文件仍叫 `key.json`，位置不变。读取拒绝规则、文档和约定都认这个名字。
- 文件格式升级为带版本号的结构，每个条目保存值和创建时间。名字就是标签。
- `serve` 与 `configure` 启动时把旧格式一次性原地迁移，之后只认新格式。
- 迁移不改配置文件，存量条目保留原来的名字。

### 稳定名字与原地轮换

- 条目名稳定。换密钥是在原条目上替换值，不再新建条目。
- 热应用除了看引用有没有变，还要看被引用条目的值有没有变。值变了，使用它的连接就重新建立。
- 一个条目被多处使用时，轮换对所有使用处同时生效。
- 手工改 `key.json` 里某个条目的值，下一次热应用同样能识别。

### 录入密钥

- 所有需要密钥的输入处都是二选一：「填新密钥」或「选用已有条目」。面板与 `configure` 相同。
- 选择单独填写一个密钥时，自动创建一个 keychain 条目。
- 新条目的名字按使用处推导（例如 Provider 别名是 `openrouter`，条目就叫 `openrouter`），重名加后缀，录入时可以改。
- 用户不需要先去 keychain manager。

### 谁可以选用已有条目

面板会话与外部客户端走不同的路线：

- **面板会话**：选用已有条目不设限。能登录面板的就是管理员，这与市面上同类产品的做法一致。
- 面板里修改连接地址时，不再要求重新提交密钥。面板可以随意选用已有条目之后，这条规则新建一个连接就能绕过，留着只会让人误以为仍有防护。
- **外部 Agent 与客户端 CLI**（经 API key 或已配对客户端访问的）：只能提交新密钥，不能选用已有条目；修改连接地址时仍须在同一次请求里重新提交密钥。
- 理由：外部 Agent 可能被提示注入，信任度不等于管理员本人。不设限的话，它可以新建一个指向任意地址的连接，再选中一把已有密钥，把它带走。
- 服务器上的 `configure` 与面板一样不设限：能进服务器 shell 的人本来就能读到密钥文件。

### Keychain manager

- 放在面板的系统设置栏目。
- 列出所有条目：名字、创建时间、被哪些配置项使用。使用处由配置反推，不另外保存。
- 任何地方都不显示密钥的值。
- 可以直接新建一把暂时没人用的密钥。
- 可以轮换条目的值。
- 可以删除单个条目，但只限没有被使用的。正被使用的条目要先去使用处换掉，才能删除。「没有被使用」的判断方式与孤儿相同。
- 另有一个只读的「外部引用」列表，见下文。
- 提供一键清理孤儿密钥的按钮。

### 清理孤儿密钥

- 取消所有自动回收：写入配置不再顺带删除条目。孤儿只由显式清理移除。
- `configure` 退出时也不再清理。填了密钥却没保存就退出，留下的条目同样等显式清理。
- 孤儿的定义：磁盘上的配置文件没有引用它，**并且**运行中正在生效的配置也没有引用它。
- 判断「磁盘文件有没有引用」时看文件的原始内容，被忽略的配置段里的引用也算数。
- 配置文件无法解析时拒绝清理，不按残缺的引用集合删除。
- 清理前弹窗列出将被删除的条目名，确认后才执行。
- 清理不可撤销。

### 环境变量与外部命令

- 这两种引用不迁移，原样保留。它们存的不是密钥，而是「去哪拿密钥」的指针，指向的环境变量或外部密钥工具本身就是 keychain。
- 规则：**keychain 只管塑料碗自己保存的值**。
- manager 的「外部引用」列表只读展示它们：用在哪、是哪一种、环境变量名。外部命令的参数不展示。
- 输入处遇到这两种引用时显示只读状态（例如「由环境变量 X 提供」），可以替换成 keychain 条目。
- 面板不能新建这两种引用，只能在配置文件里手写。理由是安全：能写外部命令等于面板可以执行任意程序；能写环境变量则可以把别的环境变量当作密钥发往自己指定的地址。
- 孤儿清理不碰它们。
- 轮换语义不变：环境变量要重启才生效；外部命令在引用变化或重启时重新执行。值变化的检测只对 keychain 条目做，不为此在每次热应用时执行外部命令。

### 这一期不做

- 条目建好之后的改名。
- 图片配置里自己的那层凭据名，保持原样。
- 条目的备注等额外信息。
