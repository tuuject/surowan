# 让塑料碗知道自己的版本号

## 为什么要做？

塑料碗的 Public Release 临近，为了让用户方便的知道自己所运行的塑料碗版本、反馈问题、检查更新，需要一种机制让塑料碗知道自己的版本号。

## 希望实现什么？

实现一个多层次的版本号感知机制。

请看下面伪代码：

```javascript
function 获取版本号() {
  // 正式版本的 Docker Image 打包，会包含一个 version 文件，在打包过程写入
  // Version: v1.0.0 / Channel: Release
  // Version: v0.0.0-next-20261102190940 / Channel: Staging
  if (塑料碗代码根目录下有version文件) {
    return 获取version文件内容();
  }
  if (塑料碗代码根目录是git仓库) {
    if (塑料碗所在commit有打tag) {
      // 同一 commit 可能同时有 Staging 和 Release 的 tag（先推 main 自动打 next tag，后在同一 commit 正式发版）
      // 有多个 tag 时按 Channel 优先级取：Release > Staging > Develop；同一 Channel 内取最新的版本
      // Version: v1.0.0 / Channel: Release
      // Version: v0.0.0-next-20261102190940 / Channel: Staging
      // Version: v0.0.0-develop-deadbeef / Channel: Develop
      return 按优先级获取tag版本();
    }
    // Version: v0.0.0-develop-deadbeef / Channel: Develop
    return 获取commit的hash并且声明是开发版本();
  }
  // 回退到固定的开发版本号，不读取 package.json 的 version 字段
  // Version: v0.0.0-develop / Channel: Develop
  return 固定的开发版本号();
}
```

### 项目版本号标准

遵循 semver 规范。

除此之外，对于非 Release 的 Channel，还会增加后缀：

- Staging: `v<版本号>-next-<时间戳>`
- Develop: `v<版本号>-develop-<Git Commit Hash>`

Develop Channel 的基础版本号固定为 `0.0.0`，与 package.json 无关。package.json 的 version 字段不参与版本号判断，避免开发版显示得比正式版还新。

### 展示位置

本次只在 Admin Panel 展示完整版本号与 Channel。

检查更新的基建推迟到 Phase 2。届时倾向通过 GitHub API 查询新版本，可参考 Bilisound 中已有的经验。

### User Agent 标准

发送对外的网络请求时：

- Web Fetch: `Mozilla/5.0 Surowan/<完整版本号>`
- 其它场景：`Surowan/<完整版本号>`

## FAQ

### Q1：塑料碗如何解析和比较版本号？

塑料碗不会直接将完整版本号传入 SemVer 库，而是先对版本字符串进行拆分，移除 `v` 前缀，并提取基础版本号、Channel 及附加信息。

- **Release**：按照 SemVer 规则比较版本号。
- **Staging**：优先比较基础 SemVer 版本号；当基础版本号相同时，再比较构建时间戳，时间戳越晚，版本越新。
- **Develop**：使用 Git Commit Hash 标识具体版本，不支持版本更新检查。

### Q2：Git Tag 模式如何确定当前版本？

Git Tag 模式只识别**精确指向当前 `HEAD` Commit 的 Tag**，不会向 Git 历史中回溯查找最近的 Tag。

- 如果当前 `HEAD` 存在 Tag，则按 Channel 优先级（Release > Staging > Develop）选取 Tag，同一 Channel 内取最新的版本，再解析版本号及 Channel。
- 如果当前 `HEAD` 不存在 Tag，则使用当前 Commit Hash 生成 Develop 版本号。
- 如果代码目录不是 Git 仓库，则回退到固定的 `v0.0.0-develop`。

这一规则确保未打 Tag 的开发提交不会被错误识别为历史发行版本。
