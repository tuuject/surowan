# telegram 配置可选

## 为什么要做？

塑料碗目前必须配置 Telegram Provider 才能运行。只想在虚拟群聊（Playground 房间）里试用的用户，也得先申请 Telegram bot 并填好凭据，才能把塑料碗跑起来。

## 希望实现什么？

用户可以完全不配置 Telegram Provider，只通过虚拟群聊试用塑料碗。

## 打算怎么做？

- 配置文件里的 `telegram` 字段从必填改为可选。
- 不配置 `telegram` 字段、token 置空或 token 无效，都是合法状态：此时塑料碗不发起任何 invocation，虚拟群聊除外，也不运行 grammy 实例。
- `telegram` 节里的 chats 可以一直为空，不再按配置错误报错；chats 为空时不处理任何 Chat。首次在面板配置 Telegram 时，用户往往要等 bot 跑起来、拉进群之后才知道 Chat ID。
- 面板不提供删掉整个 `telegram` 配置的功能。
- `--playground-only` 启动形态完全砍掉：只跑虚拟群聊改为由上述状态触发，不再有单独的启动形态。这个参数从未公开，塑料碗也还没有 public release，直接移除，不做兼容。
- `admin` 配置从可选改为必填：管理面板是塑料碗的重要部分，也是虚拟群聊的唯一入口。`admin.enabled` 保留，按原来的含义工作，但改为可选字段，默认为 true。现有配置没写 `admin` 的，升级后直接报错，在升级说明里写清怎么改。
- 面板必开之后，没有建好管理员账号时，第一个访问面板的人就能创建管理员。这个暴露窗口算运维责任，本 PRD 不处理。
- 面板关闭（`admin.enabled: false`）且 Telegram 处于停用时，按配置错误处理：日志报错 `Surowan is useless if neither admin panel is enabled nor telegram is configured`，服务不启动。
  - 这条只针对 Telegram 处于停用。面板关闭时 Telegram 处于配置异常或网络异常，不触发这条，也不做额外处理。
  - 将来接入其他 IM 后，这条扩展为：只有当 Admin Panel 被关闭，且所有 IM Provider 都被主动停用时，才拒绝启动。
  - 用户文档不在用户手册里介绍关闭面板（`enabled` 不写默认就是 true），只在配置文件参考里提一句。关掉面板属于把灯泡放嘴巴里面。
- Telegram 的连接状态分四种：
  - 停用：没有 `telegram` 字段，或 Bot Token 为空。配置文件里没有 `telegram` 字段时，服务启动后默认就处于停用状态。
  - 正常：token 有效，实例在运行。
  - 网络异常：连不上 Telegram 服务器。
  - 配置异常：Telegram 返回 401（token 被拒）或 409（同一个 token 正在别处收消息），或者 token 来源取不到（例如环境变量没设、命令执行失败）。
- 连接状态的 flag 要为后续接入 Discord、WhatsApp、Slack 等其他 IM 留好位置：每个 IM 各自一份状态，用 namespace 之类的方案区分，互不影响。Telegram 的状态变化不影响其他 IM，反之亦然。
- `telegram` 配置以管理面板为主入口；面板应用配置时，按连接状态迁移 grammy 实例：
  - 正常（token a）→ 正常（token b）：立刻重启实例（先停止当前正在运行的 Telegram 聊天 invocation），改用 token b；重启包含一次停止，已经排队、还没运行的 invocation 一并作废，不交给新 bot 处理；
  - 正常 → 停用或配置异常：立刻停止实例，立刻停止当前正在运行的 Telegram 聊天 invocation；
  - 停用或配置异常 → 正常：立刻启动实例，改用 token b。
- token 是否被拒以 Telegram 认证结果为准。
- 网络错误一律无限重试，冷启动、应用配置和实例运行中都一样：连不上时进入网络异常，连上后自动回到正常，不需要用户手动处理。
- 实例运行中：Telegram 返回 401 或 409 时进入配置异常，按「正常 → 配置异常」的路径处理。服务不再因此退出。
- 进程冷启动时处于停用或配置异常：与运行态一致，服务照常启动、不运行 grammy 实例。
- 警告：
  - 停用不发警告：这是用户主动的选择。
  - 网络异常与配置异常用常态警告：只反映当前状态，不能标为已读，状态解除后自动消失。
  - 文案按错误原因拆分：网络异常写「未能成功连接 Telegram 服务器」；401 写「你的 Telegram Token 已被吊销或无效」；409 写「这个 Telegram Token 正在被其他程序使用」；token 来源取不到写「无法读取 Telegram Token」（这三句文案暂定，可以再调）。
- 实例从停用或配置异常进入正常，或 a → b 切换后用 token b 启动时，都补拉积压消息，与进程冷启动的补偿拉取一致，但控制数量：每个群组最多收录 100 条（暂定值，可以再调）。补拉是为了让塑料碗有充足的上下文，知道群里最近一小段时间讨论了什么。
- 启动与重启都指 grammy 实例，不是塑料碗服务：塑料碗服务全程保持运行，任何状态迁移都不要求用户手动重启塑料碗。
- 实例停止时全部作废：已经批准、还没送到 Telegram 的消息不再投递，已经排队、还没运行的 invocation 一并作废。
- 实例停止期间，Telegram 对话里由模型设定的 Alarm 这类定时任务到期时先挂起，实例恢复后再补投。

### 支线任务：服务端 CLI 的管理员账号入口

给塑料碗服务端 CLI（不是塑料碗工具 CLI）实现一个单一的创建管理员账号入口：

- 还没有管理员账号时，创建账号。
- 已经创建过时，重置用户名和密码。
- 另加一个参数，用来注销所有 passkey。
- 无论是否注销 passkey，每次执行都注销所有登录会话。
- 塑料碗服务运行时拒绝执行，要先停服务。
- 用一个新命令实现，取代现有的 `admin-reset`，旧命令移除。

在服务器上直接用 CLI 操作，不是首次部署就是 recovery，所以注销全部会话、要求先停服务都是合理的代价。
