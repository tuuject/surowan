# /ask 显式唤起

## 为什么要做？

塑料碗现在的表现是「自己读群里的空气，判断是否回答」。要让更多的人能够接纳基于 LLM 的群宠，可以从显式互动的方式开始。当大家发现其实塑料碗的表现没有那么烦人的时候，或许大家的信心就能上来。

这样的表现和「塑料碗会自己读群里的空气判断是否回答」完全相悖，这一点是已知并接受的。

## 希望实现什么？

- 管理员可以把塑料碗设置为完全不被群友消息触发的模式。
- 在这个模式下，群友使用 `/ask` 这个 Bot 命令显式唤起塑料碗，与它互动。
- 开启了 `/ignoreme` 的群友，也可以使用 `/ask` 显式地和塑料碗互动。

## 打算怎么做？

### 用户的想法

- 这个模式下，没有用 `/ask` 的群友消息照常保存，塑料碗被唤起时作为历史看到；群聊记忆照常整理。
- `/ask` 的机制跟直接 @ 塑料碗导致的强制唤起是一样的。唯一的区别是：开了 `/ignoreme` 的用户，@ 塑料碗、回复塑料碗的消息、关键词触发都不会得到回应，但是使用 `/ask` 会。
- 这个模式下，@ 塑料碗、回复塑料碗的消息、触发关键词都不能唤起，只有 `/ask` 能。
- 开了 `/ignoreme` 的群友要回复塑料碗的消息，还得再显式使用 `/ask` 命令。
- 在完全不开启主动回复的群聊，内部抽象可以这样做：发起一个 0 秒的 Bucket，里面只有这一条消息。因为使用 `/ask` 命令的心智模型是，要在一条消息把整个问题说出来。所以这个模式下 `/ask` 之后没有注意力窗口，一条 `/ask` 换一次回应。

### 现状（agent 核对源码）

- 现在已经可以把群收窄到「活跃时段外，只有 @ 塑料碗、回复塑料碗发过的消息、命中触发关键词才唤起」。唤起后有一段注意力窗口，窗口内其它群友的消息也能触发。没有「完全不被触发」这一档。
- 没有触发塑料碗的消息照常保存，下次被唤起时作为历史进入模型视野；开了群聊记忆的群，这些消息还会被整理成摘要。
- 开启 `/ignoreme` 的成员，本人的消息不保存，模型看不到。目前只有 `/ignoreme` 和 `/unignoreme` 两条命令还能到达塑料碗。
- 现有的 Bot 命令都由塑料碗自己给出固定回应，不交给模型，命令消息本身也不作为聊天消息保存。`/ask` 会是第一条把内容交给模型的命令。
- Bucket 的收集时长现在是全局设置，允许取 0；每个 Bucket 在开启时记下自己的时长，所以单独给某个 Bucket 用 0 秒是成立的。
- 现在新开 Bucket 时，会把此前没进过任何 Bucket 的其它 Bot 的消息一并带进来。要做到「里面只有这一条消息」，这个模式下不能带。
