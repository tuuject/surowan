# 群聊记忆

## 为什么要做？

塑料碗目前缺乏跨 Invocation 回忆群聊历史事件的能力。

在具有持续共同语境的群聊中，过去发生的讨论可能对未来的对话仍然有意义。

但不是所有群聊都需要长期记忆。例如，用户支持群和大型 Telegram 群可能缺乏使用群聊记忆的实际价值。

因此，群聊记忆应当是一项可选能力，而不是所有 Chat 都必须启用的基础功能。

## 希望实现什么？

### 1. 记录群聊中发生的事件

群聊记忆以日期组织，记录当天发生过的讨论或事件。

例如：

```markdown
# 2026-10-01

- Natu 和 tcdw 讨论了 eSIM 的话题。（消息：4005~4114）
- 飞飞和 tcdw 讨论了 X 涨粉策略的问题。（消息：4123~4145）
```

每条记录包含简短的事件描述，以及对应的原始消息范围。

### 2. 两层渐进式披露

群聊记忆采用两层渐进式披露：

**第一层：当天发生了什么**

模型能够获取某一天发生过的事件摘要，以及各事件对应的消息范围。

**第二层：当时的聊天记录区间**

当模型需要了解某个事件的具体内容时，可以使用工具读取该事件对应的原始聊天记录区间。

事件摘要承担索引作用，不要求包含讨论的全部细节。

### 3. 按 Chat 选择启用

群聊记忆不是所有 Chat 的必需能力。

管理员可以根据群聊的实际用途，决定是否启用群聊记忆。

### 4. 内部插件化

群聊记忆作为塑料碗内部的可选插件能力实现。

具体记忆服务可以使用 EverOS 等第三方系统，不要求塑料碗自行实现全部记忆处理机制。

## 暂不决定

以下事项尚未确定，不在本 PRD 中提前作出产品决策：

- 使用 EverOS、其他第三方记忆服务，还是自研实现。
- 是否需要统一的记忆 Provider 接口。
- 如何将聊天记录划分为事件，以及何时生成摘要。
- 如何存储、保留和清理原始聊天记录。
- 记忆的检索方式及其在 Invocation 中的触发机制。
- 群友档案的生成、组织与更新规则。

## 与其他功能的关系

群聊记忆与 Memo Pad 是不同的能力。

Memo Pad 用于主动保存需要保留的资料和工作信息；群聊记忆用于记录和回顾群聊中发生的事件。

群友档案也不在本 PRD 的范围内。
