# 主动回复抽卡审计

> **状态：on hold（2026-10-24）**
>
> 这个功能性价比不高。实际观察下来，概率回复是符合预期的：某个大型群聊可以稳定低频触发 Invocation。所以先暂停，下面的内容保留到暂停时为止，重新启动前需要再确认一遍。

## 为什么要做？

塑料碗的概率回复系统，目前没有办法进行审计。

这个审计主要是为了 debug。

## 希望实现什么？

- 能够知道抽卡多少次才发起了这次 Invocation。
- 最好能知道某一次抽卡的几率达到了多少，包括失败的尝试。

## 打算怎么做？

### 用户的想法

- 不单独建表，直接记录在 Invocation 上。
- 每个 Invocation 记录：
  - 这一次抽卡的概率；
  - 这一次是否触发了保底机制；
  - 之前没抽中的几次的概率。
- 可以接受旧数据没有记录：功能上线前的 Invocation 不补数据。
- 没抽中的几次在命中前存储在一个临时文件里，命中时一并写进那个 Invocation。命中前它们在审计里看不到。
  - 因为有很多群组，所以要建立一个单独的文件夹。
  - 文件夹要先确认是否存在，再写入文件。
- 修改概率配置导致计数清零时，暂存的未中记录直接丢弃，保持记录与计数一致。
- 直接触发（@、Reply、关键词）和功能未启用的 Invocation 不抽卡，只记一个结果标签（直接触发 / 未启用），不记概率。这样能和上线前的旧数据区分开。
- Invocation 只记开局那一抽。运行中吸收新 Bucket 前的抽卡和普通未中一样处理，吸收时抽中的那几抽不记在 Invocation 上。

### Agent 的提议（未经用户确认）

以下内容是 agent 的方案草稿，不代表已确认的设计。

**现状**

- 每次抽卡的第几抽、概率、是否保底，只打在进程日志里，不保存。日志滚掉就查不到。
- 没抽中时，审计里只能看到这批消息「被概率挡掉了」，看不到当时的概率。
- 抽中时不留任何痕迹，Invocation 上看不出是第几抽。
- 每个 Chat 只保存当前连续没抽中的次数，抽中即清零，历史无法反推。

**提议**

- 除概率外，同时记录实际抽出的随机数（保底时为空），用来看差多少没中。
- 计数按 Chat 算，同一 Forum 下各 Topic 共用。之前没抽中的几次可能来自别的 Topic，建议每一次都能回查到当时那批消息。
- 查看入口用现有的命令行审计脚本，先不做 Admin Panel：查某个 Invocation 时显示这一次的概率、是否保底，并列出之前没抽中的几次。

## 还有什么没想清楚？

- 是否采纳 agent 的其余提议（记录随机数、能回查当时那批消息、只做命令行审计脚本入口）？整体或逐条。
- 暂存未中记录的临时文件，是否同时作为抽卡状态的唯一来源？用户提出它也可以用来在塑料碗突然结束后恢复抽卡状态。agent 指出：现在每个 Chat 的连续未中次数已经存在数据库里，崩溃后能恢复。如果让文件成为唯一来源，计数和记录永远一致，但文件必须放在塑料碗自己的数据目录里，并且要考虑是否纳入备份。
