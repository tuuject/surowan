# 生图参考素材改进

## 为什么要做？

- 生成图片时，可以引用的素材只有最近八个，更早的选不到。
- 在 web admin 点击选用素材以后，文本框压根不会出现引用的地方，看不出它在句子的哪里被用到。
- 在群里叫塑料碗画画时，塑料碗不知道有哪些素材可以用。

## 希望实现什么？

- 可以从所有的历史素材中挑选一个出来引用，而不只是最近八个。
- 素材被使用的时候，文本框里能体现出它在句子的哪里被插入了。比如：

  ```text
  画一个我的自设，这是我的三视图：{{reference_image_1}}
  ```

- 每个素材可以选择是否能被 agent 看到。这样以后在群里叫塑料碗画画，塑料碗就知道要查询哪些合适的素材。
- 图片生成页的布局要进行优化，让界面变得优雅美观。

## 打算怎么做？

### 用户的想法

- 图片生成页继续显示最近的一些素材，另外有一个「更多」按钮，点开是一个 modal，用来查询之前已经有的素材。
- 点击选用素材时，把图片引用插到文本框的光标处，沿用现有的 `{{image:素材 ID}}` 写法。上面例子里的 `{{reference_image_1}}` 只是示意。
- 提交时，引用不再从文字里去掉，而是在原位换成「图 1」这样的序号称呼，序号就是这张图交给绘图模型的先后。这样绘图模型能读出哪张图对应哪句话。比如提交前：

  ```text
  画一个我的自设，这是我的三视图：{{image:3f2a…}}，背景参考这张：{{image:9c41…}}
  ```

  绘图模型收到的文字：

  ```text
  画一个我的自设，这是我的三视图：图 1，背景参考这张：图 2
  ```

- 这样做的依据是：至少 Gemini Image 可以处理顺序关系。
- 素材是否能被 agent 看到，按素材逐个选择。
- 能被 agent 看到的素材，所有 Chat 都能用。
- 把素材提升到 agent 可调用，仅限管理员在 admin panel／cli／mcp 操作。
- 群聊特定的素材暂时没有考虑到使用场景，先不做。实在不行可以叫用户使用 memo pad 等方式间接实现。
- 塑料碗按名称、描述、分类、关键词的文字来查询素材。面板补上描述和分类的填写入口。
- 增加基于工具模型的一键提取名称和关键词的做法。所以素材需要加一个单独的数据列：关键词。
- 一键提取默认用工具模型。工具模型不能看图时，一键提取不可用，并提示换一个能看图的工具模型。
- 可以允许用户临时指定，这次 AI 提炼任务用一个有图片支持的 LLM。
- 把素材提升到 agent 可调用之前，不强制先填描述。
- 之前的数据做 migration，默认不能被 agent 看到。
- 以上只涉及图片素材，提示词素材不动。
- 图片生成表单和本次生成（页面上的「本次输出」）要改成垂直排版，不再水平放在一排。
- 界面需要遵循 koi-design 规范。

### 现状（agent 核对源码）

- 图片生成页的参考图区只列最近 8 张，没有翻页和搜索。「生图素材」页能翻页看到全部，但不能从那里引用。
- 宽屏下，图片生成表单在左，「本次输出」在右侧一个固定宽度的窄栏里，两者并排；窄屏下已经是上下排。
- 点选参考图后，它出现在「已选参考图」一排标签里，不进入文本框。
- 提示词里已经可以手写 `{{image:素材 ID}}` 来引用图片。提交时这段引用会从文字里去掉，它在文字里第一次出现的位置只决定图片交给绘图模型的先后；标签里选的图排在它们后面。绘图模型拿到的是一段不含引用的文字，加上一组按顺序排好的图。
- 图片素材已经有名称、描述、分类三项，素材列表可以按这三项搜索。面板目前只能改名称，描述和分类没有填写入口。
- 图片素材是一个不分 Chat 的整体，里面有三种来历：面板上传的；群友在聊天里交给塑料碗当输入图的（自动取名「输入图 media-…」）；每次生成的输出图，包括群里触发的生成。
- 塑料碗现在只能把当前对话里出现过的图片当输入图，没有任何途径看到或查询素材。
- 素材的查看、上传、改名、归档，现在在 admin panel、cli、mcp 三处都已经能做。
- 工具模型是系统级的辅助模型，目前用于辞典融合。配置时只要求它能处理文字，不要求能看图。看图另有一个可选的视觉模型，目前用于 Sticker 与图片理解。
- 归档的素材不再出现在选择列表，已引用它的历史生成不受影响。

## 还有什么没想清楚？

暂时没有。
