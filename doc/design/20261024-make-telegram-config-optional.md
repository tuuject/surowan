# telegram 配置可选

## 为什么要做？

塑料碗目前必须配置 Telegram Provider 才能运行。只想在虚拟群聊（Playground 房间）里试用的用户，也得先申请 Telegram bot 并填好凭据，才能把塑料碗跑起来。

## 希望实现什么？

用户可以完全不配置 Telegram Provider，只通过虚拟群聊试用塑料碗。

## 打算怎么做？

- 配置文件里的 `telegram` 字段从必填改为可选。
- 不配置 `telegram` 字段、token 置空或 token 无效，都是合法状态：此时塑料碗不发起任何 invocation，虚拟群聊除外，也不运行 grammy 实例。
- `telegram` 节存在时 chats 不能为空，仍按配置错误报错。
- `--playground-only` 启动形态完全砍掉：只跑虚拟群聊改为由上述状态触发，不再有单独的启动形态。
- `admin` 配置从可选改为必填，配了即开启面板（`enabled` 开关一并取消）：管理面板是塑料碗的重要部分，也是虚拟群聊的唯一入口。
- `telegram` 配置以管理面板为主入口；面板应用配置时，按 token 的有效性迁移 grammy 实例：
  - 有效 token a → 有效 token b：立刻重启实例（先停止当前正在运行的 Telegram 聊天 invocation），改用 token b；已经排队、还没运行的 invocation 保留，重启后由新 bot 继续处理；
  - 有效 token a → 无效或置空：立刻停止实例，立刻停止当前正在运行的 Telegram 聊天 invocation；
  - 无效或置空 → 有效 token b：立刻启动实例，改用 token b。
- token 的「无效」以 Telegram 认证不通过为准；应用配置时连不上 Telegram 会先重试 3 次，仍无法确认则按「有效 → 无效」的同一条路径处理（实例停止、正在运行的 invocation 停止），之后通过再次应用配置恢复。
- 进程冷启动时 token 无效或置空：与运行态一致，服务照常启动、不运行 grammy 实例，同时向用户发出面板可见的警告。
- 实例从「无效或置空」启动时补拉积压消息，与进程冷启动的补偿拉取一致，但控制数量：每个群组最多收录 100 条（暂定值，可以再调）。
- 启动与重启都指 grammy 实例，不是塑料碗服务：塑料碗服务全程保持运行，任何状态迁移都不要求用户手动重启塑料碗。
- 实例停止时全部作废：已经批准、还没送到 Telegram 的消息不再投递，已经排队、还没运行的 invocation 一并作废。
