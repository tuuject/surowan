# 模型选择页面改进

## 为什么要做？

从 Models.dev 匹配模型元数据后，过多字段需要管理员逐一确认才能保存。

切换模型后，正在进行的 Invocation 会继续用旧模型跑完，新模型要等下一次会话才能开始处理。

## 希望实现什么？

- 管理员添加模型时，参数能匹配到就直接填入，只有关键信息匹配不到才需要确认。
- 切换模型后立刻生效：正在使用旧模型的 Invocation 被终止，群友的后续会话马上由新模型处理。
- 切换行为同时适用于全局模型切换和群聊列表中该群单独设置的模型切换。

## 打算怎么做？

### Models.dev 元数据匹配

从 Models.dev 获取模型的上下文大小、最大输出大小、多模态能力和价格。

价格按以下规则写入，均无需用户确认：

- 匹配到具体 Provider：使用该 Provider 的价格。
- Models.dev 中有价格，但无法匹配具体 Provider：使用其中最高的价格（该模型在 Models.dev 各 Provider 部署中最贵的价格）。
- Models.dev 中完全没有可用价格：写入 0。

确认规则：

- 能够准确匹配到模型的详细参数，直接填入，无需用户确认。
- 价格匹配不到，按价格规则写入，无需用户确认。
- reasoning 匹配不到，按非推理模型直接保存，但向用户显示提示。
- 只有匹配不到上下文长度等关键信息（上下文大小、最大输出大小、多模态能力）时，才提示用户确认；确认后方可保存所添加的模型。

### Models.dev 地址

- Models.dev 的 API 地址可以在配置文件中指定，是可选项，不指定即为 https://models.dev/api.json。
- 支持热加载，修改后立即生效。
- Admin Panel 中在较深的入口提供修改。

### 切换模型

切换全局模型，或在群聊列表中切换该群单独设置的模型时：

- 若有正在进行的 Invocation 正在使用这个模型，先弹出模态框向用户二次确认；确认后终止这些 Invocation。
- 终止后，被终止的 Invocation 正在处理的那批消息不再获得回应，不重新处理。
- 之前委派的任务不受影响。
- 新模型直接接手该 Conversation 的现有上下文，无需迁移。若已使用的上下文超出新模型能保留的范围，下一次会话开始时自动重建。
- 群友的后续会话马上由新模型处理。

强制重建上下文的按钮是后续支线任务，不在本次范围。
