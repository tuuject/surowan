## 4. 通用规则

### 4.1 只搬不改

- 代码原样搬过去：函数体、条件、错误信息、日志字段、`await` 顺序、事务边界、注释都不变。允许的改动只有三类：import/export；把 class 私有方法抽成模块函数时新增的参数和调用；为拆分而新建的组合对象。
- 不修 bug，不重命名，不顺手整理。发现的问题写进交付报告的「发现但未处理」。
- 不靠缩短文本通过检查：不压缩、不删注释、不合并行、不缩短命名。
- 不改测试断言，不删测试，不加 `.skip`、`.only`、`.todo`。
- 拆完运行 `pnpm run lint:fix`，它只应该产生格式化改动。

### 4.2 怎么拆

- 按职责拆。先列出顶层声明，把互相调用的分成一组，每组搬进一个以主题命名的兄弟模块，例如 `send-tool.ts` → `send-tool-<topic>.ts`。一个文件要拆出三个以上新模块时，改成同名目录 `send-tool/<topic>.ts`。目录里已有命名惯例的，沿用它。
- 原文件保留主要导出（例如 `server.ts` 仍然导出 `AdminServer`），这样大部分 importer 不用动，只有用到被搬走导出的 importer 要改路径。
- 单个 class、函数或 describe 本身就超过 20 KB 的（附录 A 的「难点」列），只搬顶层声明降不下来：
  - class：把私有方法的主体抽成兄弟模块里的函数。模块函数访问不到 `#private` 字段，所以需要的状态都作为参数显式传入。class 保留原方法名，内部改为调用这个函数。公开方法、构造参数和返回值都不变。可以参照 `src/ingress/admin/` 已有的 `create…AdminHandler(deps)` 和 `*-admin.ts` 写法。
  - 不要用 mixin、`Object.assign(X.prototype, …)`、`.call(this)` 或继承来拆 class。
  - 超长方法（例如 `AgentRuntime#runInvocation`，35 KB）：按阶段切成几个顺序执行的函数，`try/finally`、`await` 顺序和事务边界原样保留。
  - React 组件：把子区块抽成组件或 hook，放到 `components/<area>/`（已有 `components/chats`、`components/models`、`components/dictionary`）。渲染出的 DOM 和文案不变。
- 新模块不能 value-import 它被拆出来的原模块，否则会形成循环依赖，加载时报 TDZ 错误。只能用 `import type` 引用类型，需要的值通过参数传入。

### 4.3 import、export 与语法

- 本地 import 保留 `.ts`/`.tsx` 后缀。类型用 `import type`（项目开了 `verbatimModuleSyntax`）。只用可擦除语法：不用 `enum`、`namespace`、构造器参数属性。
- 清理式切换：所有 importer 直接指向新模块，**不留 re-export 垫片**。唯一例外是 §5 B2 的 `schema.ts`。
- 只导出其他模块确实在用的东西。

### 4.4 同步引用

每搬走一个导出或改一个文件名，都要在全仓库搜引用并更新：

```bash
git grep -n -e '<旧文件名或符号>' -- ':!agent-doc/devlogs' ':!agent-doc/design'
```

- 需要同步的位置：`AGENTS.md`、`agent-doc/*.md`（写了文件路径和符号位置的地方）、`skills/`、`apps/docs/`、`.github/workflows/`，以及测试里按路径读源码或启动子进程的字符串。例如 `test/serve-signals.test.ts` 按路径 import `runtime-host.ts` 里的 `watchStopSignals`。
- `agent-doc/devlogs/` 和 `agent-doc/design/` 是冻结的历史文档，不要改。

### 4.5 必须停下来报告的情况

- 不改行为就降不到限制以内。
- 需要改测试断言或测试的预期行为（`im-host.ts` 例外，做法见 §5 B2）。
- 测试或 e2e 失败，而且原因不是 import 路径。
- 认为某个文件应该加进 `IGNORED`。
- 不确定某次搬动是否改变了执行顺序或对象身份。
