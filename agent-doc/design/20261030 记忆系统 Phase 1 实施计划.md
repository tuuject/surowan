# 记忆系统 Phase 1 实施计划

PRD：[doc/design/20261030-memory-system-phase-1.md](../../doc/design/20261030-memory-system-phase-1.md)。本文是实现契约，不重复 PRD 的产品理由。

## 范围

只做 Memo Pad：按 Chat 隔离、Topic 共用；`summary` / `detail`；可选期限；旧 `memories` 迁移；短期记忆注入；查询/读详情原语；增删改经 `execute`；Blob 存储与 `pwblob://`；Admin CRUD 与 Blob 访问；Chat 热删除与配置删除停跑。

不做：群友档案、群聊记忆、Dreaming、RAG、全局 Memo Pad、Blob 全局提升、外部文件交换、孤儿数据管理页面。

## 命名与标识

- 表：`memo_pad_entries`、`memo_blobs`。
- Memo id：沿用 `mem_<32hex>`；迁移保留旧 id。
- Blob id：`blb_<32hex>`；URI：`pwblob://blb_<32hex>`。
- Blob 文件根：`<data_dir>/images/memo-blobs/<chatId>/<blobId>.<ext>`。放在 `images/` 下，随现有 `.images/` 备份快照携带。
- `chatId` 一律指内部 `chats.id`（`ContextIdentity.internalChatId`），不是 Telegram chat id。

## 数据模型

```sql
memo_pad_entries(
  id TEXT PK,
  chat_id INTEGER NOT NULL REFERENCES chats(id) ON DELETE CASCADE,
  summary TEXT NOT NULL CHECK(length(summary) BETWEEN 1 AND 150),
  detail TEXT NOT NULL CHECK(length(detail) BETWEEN 1 AND 32768),
  created_at TEXT NOT NULL,
  expires_at TEXT,              -- NULL = 长期；非空 = 短期
  updated_at TEXT NOT NULL,
  CHECK(expires_at IS NULL OR expires_at > created_at)
)

memo_blobs(
  id TEXT PK,
  chat_id INTEGER NOT NULL REFERENCES chats(id) ON DELETE CASCADE,
  sha256 TEXT NOT NULL,
  mime TEXT NOT NULL,
  byte_size INTEGER NOT NULL,
  storage_path TEXT NOT NULL,   -- 相对 <data_dir>/images/memo-blobs
  created_at TEXT NOT NULL,
  UNIQUE(chat_id, sha256)
)
```

`conversation_contexts` 增加：

- `memo_refresh_seq INTEGER`：最近一次渲染完整列表的批次 `seq`。
- `memo_state_json TEXT`：最近一次已告知模型的短期记忆状态（`{id,summary,updatedAt,createdAt}[]`）。
- `memo_refresh_pending INTEGER NOT NULL DEFAULT 0`：强制刷新；配置移除 Chat 时置 1。

刷新判据（渲染批次 `seq` 时）：

```text
refresh = pending
       || refresh_seq IS NULL
       || refresh_seq < header.headSeq   // 带列表的批次已被 GC
```

Context 重建会把三个字段复位（`refresh_pending = 1`）。刷新只在消息落盘时提交状态（`persistMessage`），渲染本身只读；同一轮连续注入多个批次时，内存中的 header 同步推进，避免重复渲染同一列表/增量，数据库仍等落盘才提交。

## 注入

- 完整列表只含短期记忆（`expires_at IS NOT NULL AND expires_at > now`），按 `created_at, id` 升序。
- 列表放在 `<runtime_state>` 内，标签 `<memo_list>`；每行 `- <id>: <escaped summary>`。
- 预算：`floor(contextWindow * 0.1)` 字符（PRD：每字 1 Token）。超限从最早开始隐藏，末尾提示 `[N earlier short-term memories are not shown; use search_memory to find them]`。
- 非刷新批次只渲染增量块 `<memo_updates>`，追加在 `</untrusted_new_messages>` 之后；行格式 `+`/`~`/`- <id>: <escaped summary>`。无变化不渲染。
- 增量按 `memo_state_json` 比较；`id` 新增/`updatedAt` 变化/消失分别视为 added/updated/removed。状态在落盘时推进，因此变化跨 Invocation 保留在历史里直到 GC。
- 长期记忆不自动注入。列表为空时三个标签都不出现。

## Tool

原语（直接暴露，不经 `execute`）：

- `search_memory`：`{ keywords?: string[], from?: string, to?: string, limit?: number }`。关键词匹配 `summary` 与 `detail`，大小写不敏感子串；单个关键词必须命中；多个关键词命中数 `>= ceil(n/2)`。日期区间过滤 `created_at`。返回 id/summary/期限/时间，不含 detail。
- `read_memory`：`{ id }`。返回 summary + detail，并记录本 Invocation 已读（`id -> updatedAt`）。

经 `execute` 的内部能力：

- `add_memo`：`{ summary, detail, ttl_seconds? }`；省略 `ttl_seconds` = 永久。
- `update_memo`：`{ id, summary?, detail?, ttl_seconds? }`；`ttl_seconds: null` = 转永久；必须先 `read_memory`，且 `updatedAt` 与已读记录一致（Admin 修改后自动失效）。
- `delete_memo`：`{ id }`；不要求已读。
- `save_memo_image`：`{ image_ref }`，只接受当前 Context 授权的 `img_`，复制为 Chat 所有的 Blob，返回 `pwblob://` URI。模型自行把 URI 写进 detail。

写入（add/update/delete/save）在 Telegram 上必须通过 `resolveChatConfig` 确认 Chat 仍在配置中；Playground 不适用。

`read_image` 的 `image_ref` 扩展接受 `pwblob://...`，按当前 `internalChatId` 鉴权后分析 Blob。

## Blob 清理

- 更新/删除 Memo 后，对旧 detail 中不再出现在新 detail 的 Blob 检查同 Chat 其他条目是否仍引用；无人引用则删行再删文件。
- `sweep(chatId?)` 清理无任何 `memo_pad_entries.detail` 引用的行与文件，并跳过创建不足 10 分钟的 Blob（`save_memo_image` 与写入 detail 之间的窗口）；在启动、备份与写路径机会性调用。
- Admin 删除 Chat：配置热移除 → 停 Invocation/长任务 → 删除 `chats` 行（级联 Memo/Blob 行）→ 删除该 Chat 的 Blob 文件。
- 手改配置删除 Chat：只停运行并把 `memo_refresh_pending` 置 1，不删数据。

## Admin

- `/api/memories` 改为 Memo Pad：列表返回 summary/detail/期限；过滤 `chat`、`state`（`active`/`expired`/`short`/`long`）；POST/PUT/DELETE 语义见上。
- `GET /api/memories/blobs/:id/content`：仅 Panel Session；校验 Blob 行存在；`private, no-store` + `nosniff`。
- 前端 `/memories` 页展示 summary 列表、详情弹窗；详情里的 `pwblob://` 转成 `/api/memories/blobs/<id>/content`，Markdown 图片语法渲染为 `<img>`；删除 Chat 的确认弹窗明确提示 Memo Pad 与 Blob 一并删除。
- `memory_ttl_warning_days` 保留为兼容配置但不再使用；Harness 不再暴露，Admin 不再有 `long_ttl` 警告。

## 兼容与迁移

- 迁移 `046_memo_pad.sql`：建表、加 Context 列、把 `memories` 按 `conversations.chat_id` 聚合迁入（`summary = detail = content`，保留 `expires_at`），删除 `memories`。配置中的旧 Chat id 通过 `chat_migrations` 解析到实际存储行；删除与停跑同时处理旧、新 id。
- 旧 `mem_` id、旧 TTL 原样保留。
