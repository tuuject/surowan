# Models 页全量热切换交付报告

> 日期：2026-09-21
> 对应计划：[20260921 Models 页全量热切换设计计划](20260921%20Models%20页全量热切换设计计划.md)
> 状态：已实施。后端（模型注册表进入配置快照、Provider/agent/vision 全量热切换、`secret_unresolved`、discover 语义）与前端（Models 页去掉待重启路径、e2e）均已完成；本报告记录与计划的偏差、实施选择与待决问题的结论。

## 完成范围

按计划的「实施顺序」推进，每步结束时 `pnpm run check`、`pnpm run lint`、`pnpm test` 通过；动到前端的部分另外跑了 `pnpm run admin:build` 与 `pnpm run admin:test:e2e`。

1. **注册表进入快照**：`RuntimeConfiguration` 增加 `models` 与 `visionModel`（`ConfigurationModels`），`RuntimeConfigurationStore` 的构造函数与 `publish` 接收完整快照。`ModelRegistry` 接口、`createModelRegistry` 与原地 `setProvider` 全部删除，改为 `buildModelRegistry(config, previous, secrets)`（`previous` 为 `null` 时等价于启动路径）。调用方 `AgentRuntime`（改读 `snapshot.models`）、`AgentModelSwitcher`（只接收 store）、`MediaService`（每次分析取一次当前快照）、`AdminServer`（去掉 `models` 选项）、`ConfigReloader`、`application.ts`、`doctor.ts` 全部迁移。
2. **连接字段与 Provider 增删热切换**：`config-diff.ts` 把 `providers.` 前缀、`agent.provider` / `agent.model`、`vision.provider` / `vision.model` / `vision.max_output_tokens` 记为 hot，删除 `InUseModels` / `isInUse` / `providerIsNew` 与 `candidateAgentProvider` / `candidateAgentModel`。reload 在锁内构建新注册表并随配置一起发布；新增错误码 `secret_unresolved`（`CONFIG_WRITE_STATUS` 与 `MODEL_ERROR_STATUS` 都是 422）；`POST /providers/discover` 的 saved 模式改为比对文件与 active 的连接字段（`connection_not_applied`），`ProviderWriteContext.models` / `restartRequired` 换成当前快照。
3. **在用模型与 vision 热切换**：删除在用模型保护（模型新增、修改、删除都是 hot，candidate 取文件里的定义）；`MediaService` 删除 `#models` / `#model` / `#analysisVersion`，每次分析开始时取一次快照（模型 + `analysis_version`），聊天分析与后台 Sticker 索引同一规则。
4. **前端与文档**：Models 页删除所有「待重启」专属逻辑（`providerPendingRestart` / `modelPendingRestart`、两处徽章、连接卡与向导文案、向导的 `saved` 步骤与「Restart now」按钮）；`configuration.md`、`admin-panel.md`、`architecture.md`、`telegram-agent-flow.md`、`operations.md`、`verification.md`、`apps/admin-next/README.md` 与历史索引同步更新。

## 与计划的偏差与实现选择

1. **复用规则复用「整个 Provider 对象」，而不是重新 `createProvider` / `aliasBuiltinProvider`**。计划 S2 写「复用旧 Provider 对象上的 `baseUrl`、`headers`、`auth`，只用新的 `models[]` 重新构建」。实现改为：连接字段完全相同时（`sameConnection`，比较「除 `models` 外的全部字段」），新注册表直接放 `{ ...existing, getModels: () => models }`。三个理由：(a)「不重新解析 SecretRef」变成构造性事实，而不是靠复用三个字段推导；(b) 连接字段没变时 transport 本就与旧对象一致——builtin 的 `streamSimple` 绑定的是同一个 Pi 目录条目，custom 的 adapter 由连接字段里的 `api` 决定，重建没有行为差异；(c) 测试里的 faux Provider 因此能在 reload 后继续工作，否则「reload 后同一 Invocation 继续跑」的用例会打到真实网络。模型列表在构建时算好并被闭包捕获，与旧实现一样保持对象标识稳定（`getModel` 每次调用都会走 `getModels()`）。
2. **`HOT_PREFIXES` 增加 `providers.`**。计划说「连接字段走 hot」；实现把整个 `providers.` 前缀列为 hot，与「providers 全部字段热切换」的文档口径一致，也避免逐个列举连接字段时漏掉 builtin 的 `provider`（Pi 供应商 id）。
3. **「钉住」测试用两个本地 HTTP 端点，而不是 faux 记录 baseUrl/key**。计划设想用 faux 观察每次请求看到的 baseUrl 与 key，但 builtin 别名的连接字段只有 `api_key`，且换 key 会按目录重建 Provider（faux 会被真实目录 Provider 取代），无法观察。实现改为：起两个 loopback OpenAI-completions 端点（记录 path 与 `authorization`），Invocation 第一轮响应返回之前由端点自己触发 patch + reload，断言第二轮仍打到旧地址、旧 key（`Bearer key-a`），之后开始的 Invocation 打到新地址、新 key。另外保留一个 faux 用例断言运行中的 run 钉住的是同一个模型对象。
4. **`ProviderWriteContext` 携带当前快照**。discover 需要 active 的连接字段与凭据，两者都在快照里；`restartRequired` 随之删除（不再有「待重启的连接」这个概念）。
5. **`vision.max_output_tokens` 每次分析现读**：加入 hot 清单，`MediaService` 在分析开始时读它，与这次分析的模型、缓存版本一起确定。
6. **`secrets.ts` 新增 `SecretResolutionError`**。计划只要求新错误码；为了让 reload 能区分「SecretRef 解析失败」和「其它构建失败」，`resolve()` 的三条失败路径（env 未设置、命令失败、结果为空）改为抛这个类，`#buildRegistry` 按类型映射到 `secret_unresolved`，其余仍是 `model_unusable`。
7. **`RuntimeConfigurationStore` 的构造函数接收已构建的注册表**（待决问题 2 的结论）。生产只有一条构建路径：组合根与 `doctor` 调 `buildModelRegistry(config, null, secrets)`，reload 调 `buildModelRegistry(candidate, previous, secrets)`。测试加 `test/helpers.ts` 的 `testConfigStore(initial, registry?)`（不传 registry 时按 `serve` 的路径构建）与 `fauxRegistry(faux)`；26 个测试文件的构造调用是机械替换，另外 `test/context-hot-inject.test.ts` / `test/config-reload.test.ts` 保留了一个 `MutableModels` 句柄来替换 faux。
8. **Models 页编辑弹窗的说明文案**（计划未点名）：原文写「改用在用的模型要等重启」，与新行为矛盾，一并改成「改动立即生效，已在运行的 Invocation 继续用它启动时的定义」。
9. **e2e 的「Applied」断言改为 `appliedToast(page)`**（计划未点名）：`helpers.ts` 新增该 locator，把断言限定在 Sonner 的 `[data-sonner-toast]` 容器内。上面的文案改动让弹窗说明里出现了「applied」，而 Playwright 的 `getByText` 是大小写不敏感的子串匹配，于是 `getByText('Applied').first()` 会先命中弹窗说明、在写入尚未落地时就让断言通过——后续的 API 读回于是读到旧值（`04-writes` 与 `08-models` 的 6 处断言一并改成限定容器）。
10. **提交粒度：3 个提交，而不是计划的 4 个**（经确认）。计划的「实施顺序」要求每步单独提交，但步骤 1–3 的改动落在同一批文件（`config-reload.ts`、`providers.ts`、`config-diff.ts`、`providers-admin.ts` 等），单独提交步骤 1 必须把当时已被步骤 2 删掉的旧 restart 分类代码重新写回去、跑一遍验证、再在下一步删掉。实际提交：后端（`src/` + `test/`）→ 前端与 e2e（`apps/admin-next/`）→ 文档（`agent-doc/` + `apps/admin-next/README.md`），每个提交都处于可编译、已验证的状态。

## 待决问题的结论

1. **builtin 的 `provider` 属于连接字段**：`sameConnection` 比较「除 `models` 外的全部字段」，所以 kind 相同但 `provider`（Pi 供应商 id）被手改时按新建处理——重新解析 SecretRef，并按新的目录条目构建 transport。`providers.test.ts` 的「treats a changed builtin provider id as a new connection」覆盖。
2. **构造函数接收已构建的注册表**，见偏差 7。
3. **in-flight 去重键已含 `analysis_version`**：换模型前后同一张图的并发请求键不同（`<file_unique_id>\0<analysis_version>`），各自独立分析，不会互相等待到错误结果；同一个 `analysis_version` 的并发请求仍然共享一次分析。

## 验证证据

- `pnpm run check`、`pnpm run lint`：通过。
- `pnpm test`：**41 个文件、455 个用例通过**（改动前 41 个文件、约 450 个用例；本次新增「钉住」「复用/重解析计数」「`secret_unresolved` 原子性」「vision 切换后的 `analysis_version`」「Provider 增删/改 kind/连接字段分类」等用例，删除了依赖旧行为的用例）。
- `pnpm run admin:build` 通过；`pnpm run admin:test:e2e` **90 passed**（含改写的两条 Models 页用例）。
- 关键用例：
  - **钉住**：`config-reload.test.ts` 的两个本地端点用例（旧连接跑完本轮、新连接给下一次 Invocation）+ faux 模型对象钉住用例。
  - **复用**：`providers.test.ts` 的「keeps a provider whose connection is unchanged and re-resolves no secret」「rebuilds a provider whose connection changed and resolves its secret again」，`config-reload.test.ts` 的「a connection change re-resolves exactly one provider secret」（`CountingSecrets`）。
  - **失败原子性**：`config-reload.test.ts` 的「a reload that cannot resolve a new secret leaves the running configuration alone」——`configStore.current()` 是同一个对象（generation 与注册表都不变），错误码 `secret_unresolved`。该用例的失败信息只含环境变量名，没有可脱敏的密文；`#failure` 仍然照常对 message 做 `redact`（`redacts secrets from reload errors and logs` 覆盖脱敏本身）。
  - **hot 分类**：`config-diff.test.ts` 全部改成 hot 并各自断言 candidate 取了文件里的值（新增删除 Provider、改 kind、连接字段、在用模型、vision、新 Provider 上的 agent）。
  - **vision**：`admin-providers.test.ts` 断言 `PUT /vision` 后 `restart_required` 为空且快照里的 `visionModel` 已换；`media.test.ts` 断言换模型后按新 `analysis_version` 重新分析、旧行不被命中。
  - **discover**：`admin-providers.test.ts` 用 `candidate_invalid` 制造「写入成功但未应用」，saved 模式返回 409 `connection_not_applied` 且两个本地端点都没有收到请求。
