这是一个**刻意保持简单的 Agent 短期记忆系统**。不做 embedding、RAG、importance scoring、自动总结或复杂召回。

模型自己判断什么值得记，所有当前有效的记忆直接作为一个列表注入 system prompt。

## 设计

### Memory 数据与工具

每条 memory 至少包含：

```ts
{
  id: string
  content: string
  createdAt: Date
  expiresAt: Date
}
```

Agent 有两个基本操作：

```text
add_memory(content, ttl?)
delete_memory(id)
```

其中：

* `add_memory` 默认 TTL **1 天**；
* Prompt 要求模型原则上把单条 memory 控制在 **100 字以内**；
* Tool 层有 **150 字 hard limit**；
* 每条 memory 有唯一 ID，因此 Agent 可以主动删除已经错误、失效或不再需要的记忆；
* 暂时不需要 `update_memory`，需要修改时可以 delete + add。

### 遗忘机制

有两条路径：

**自然遗忘：** TTL 到期后自动消失。

**主动遗忘：** Agent 发现某条记忆已经失效时调用 `delete_memory(id)`。

因此 memory 不是 append-only 的聊天摘要，而是 Agent 自己维护的一小块临时状态。

### 长期记忆的处理

Agent 可以主动设置很长的 TTL，**系统不直接禁止**。

但 TTL 超过一定阈值时，在管理控制台产生 warning，由管理员判断：

* 保留这条长 TTL memory；
* 删除；
* 如果确实属于长期稳定的知识/行为规则，则提升进 `agents.md`。

也就是说：

> **模型有长期记忆的提名权，人类有长期记忆的固化权。**

`memory` 是运行过程中产生、允许遗忘的信息；`agents.md` 是经过人工审核、应该长期成立的信息。

### Prompt 注入与 Cache

当前有效 memory **全部注入 system prompt**，不做相关性检索。

为了利用模型提供商的 prefix cache，内容按照稳定程度排列：

```text
固定 system prompt
↓
会话开始时间
↓
memory 列表
```

Memory 内部严格按照 **创建时间升序**排列。

这样正常的 `add_memory` 基本等价于在列表末尾 append：

```text
mem_001
mem_002
mem_003
+ mem_004
```

不会因为 relevance、importance、剩余 TTL 等因素导致已有 memory 重排，因此尽可能保留 prefix cache。只有 TTL 到期和 `delete_memory` 等操作会破坏删除位置之后的缓存前缀，不为此额外引入 tombstone 等复杂机制。

整体上，这套设计的特点就是：**Agent 自己记、自己忘，TTL 负责兜底遗忘；短期记忆自动化，长期记忆人工审核；所有记忆直接塞上下文，并用稳定排序顺便照顾 prefix cache。**
