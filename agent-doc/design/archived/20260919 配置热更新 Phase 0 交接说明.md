## 目标

Phase 0 是结构重构，为 Phase 1 的 `reloadFromFile()` 铺路：

1. 新增 `RuntimeConfigurationStore`，作为运行期读取配置的唯一入口。
2. invocation 在 `queued → running` 时取得配置快照，运行期间的配置读取只从快照取。
3. 修复两个现存问题：复用缓存 Agent 时没有重绑 `thinkingLevel`；`validateAdditionalTools` 使用启动时固定的模型。

Phase 0 结束时配置在运行期间仍然不会变化。除第 3 点的两个修复外，外部行为不变。

## 不在本阶段范围

以下内容都不要做：

- `reloadFromFile()`、任何 reload 入口、Admin 端点。
- `/model` 的行为：内存 override 与 `/model reset` 保持原样。
- `invocations.config_hash` 的写入时机：仍在创建 invocation（queued）时写入。
- 数据库 Schema 与迁移、模型禁用表、Vision 可选、`MutableModels`、MCP。
- 依赖注入框架。组合根仍然是 `src/application.ts`。

## 设计

### RuntimeConfigurationStore

新文件 `src/platform/runtime-config.ts`，只实现下面这些：

```ts
export interface RuntimeConfiguration {
  readonly generation: number; // Phase 0 恒为 1
  readonly hash: string; // 即 LoadedConfig.hash
  readonly config: RawConfig;
}

export type InvocationConfigSnapshot = RuntimeConfiguration;

export class RuntimeConfigurationStore {
  constructor(initial: { readonly config: RawConfig; readonly hash: string });
  current(): RuntimeConfiguration;
  beginInvocation(): InvocationConfigSnapshot; // 返回 current() 的同一个对象引用
}
```

- 构造参数只要 `config` 与 `hash`：`LoadedConfig` 本身满足这个形状，`application.ts` 直接传 `loaded`；测试里没有 `LoadedConfig` 的地方传 `{ config, hash: 'hash' }` 即可。
- 不要实现 reload、setter、订阅或事件，Phase 1 再加。
- 快照就是一个不可变对象的引用。Phase 1 发布新配置时会整体替换这个对象，已经取得的快照自然保持不变。因此任何代码都不能修改 `RawConfig` 对象本身。

### 读取规则

| 读取位置 | 取值来源 |
| --- | --- |
| invocation 运行期间：`AgentRuntime.run` 及其调用的私有方法与 hooks、`ContextBuilder` | 快照 `snapshot.config` |
| 例外：运行期间读 `agent.daily_budget.max_tokens` | `configStore.current()`，每次读取都重新取（全局配额，方案 §6.1 B 类） |
| 其它所有地方 | `configStore.current()` |

- 读取热字段的类整体改为持有 `RuntimeConfigurationStore`，删除 `RawConfig` 字段，同一个类里不能混用两种来源。
- 构造时派生的状态（`ParticipationRegistry`、allowlist map、`ContextRefStore` 的 TTL、`ConversationRuntime` 的缓存大小、Vision semaphore、Admin listener 参数等）继续在构造时从 `configStore.current().config` 取一次。
- 不读热字段的类（`StickerService`、`McpManager`、`ParticipationRegistry`、`SqliteStore`、`createModelRegistry` 等）不改。
- `resolveChatConfig(config, orm, chatId)` 的签名不变，调用方按上表传入快照或 `current()` 的 config。

### 需要切换的类

用下面的命令列出读取点，逐个核对：

```bash
grep -n "#config\|options.config" \
  src/orchestration/agent-runtime.ts src/context/context-builder.ts \
  src/orchestration/scheduler.ts src/orchestration/invocation-queue.ts \
  src/ingress/telegram-ingestion.ts src/capabilities/media/media.ts \
  src/orchestration/bot-commands.ts src/ingress/admin/server.ts \
  src/platform/model-switch.ts
```

1. **`BucketScheduler`**（`src/orchestration/scheduler.ts`）
   - 构造参数从 `(store, config, configHash, handler, attachment?)` 改为 `(store, configStore, handler, attachment?)`。
   - `InvocationHandler` 改为 `(invocationId: bigint, snapshot: InvocationConfigSnapshot, signal: AbortSignal) => Promise<InvocationOutcome>`。
   - `#launchQueued` 中把 invocation 与 bucket 设为 `running` 的 `this.#store.transaction(...)` 回调里调用 `configStore.beginInvocation()`，与状态转换在同一段同步代码中完成，然后把快照传给 handler。
   - `agent.max_concurrency` 在每轮循环读 `current()`。
2. **`InvocationQueueService`**（`src/orchestration/invocation-queue.ts`）
   - 构造参数去掉 `config` 与 `configHash`，改为 `configStore`。
   - `history_messages` 等读取改为 `current()`；`#insertInvocation` 写入的 `configHash` 改为 `current().hash`。
3. **`AgentRuntime`**（`src/orchestration/agent-runtime.ts`）
   - `AgentRuntimeOptions.config` 改为 `configStore`。
   - `run(invocationId, snapshot, signal)` 增加快照参数，并传给 `#runInvocation`。
   - `#runInvocation` 与它闭包里的 hooks 读快照。它调用的私有方法（`#sendRateLimit`、`#deferCollectingBucket`、`#createCachedAgent`、`#maybeCollect`）改为接收 config 参数，不再读实例字段。
   - `agent.daily_budget.max_tokens` 的所有读取改为 `current()`。
   - `validateAdditionalTools` 在 invocation 之外调用，读 `current()`。
   - 模型仍然在 run 开始时由 `modelSwitcher.model()` 解析，不放进快照。Phase 1 删除 override 后，模型会直接来自快照里的配置。
4. **`ContextBuilder`**（`src/context/context-builder.ts`）
   - 它的配置读取都发生在 invocation 内（`identity`、`buildSystemPrompt`、`renderInjection`）。删除 `#config` 字段，改为由这些方法接收快照的 config 参数，调用方 `AgentRuntime` 传入快照。
5. **`TelegramIngestion`**（`src/ingress/telegram-ingestion.ts`）：构造参数改为 `configStore`；运行期读取改为 `current()`；allowlist map 与 `ParticipationRegistry` 在构造时生成。
6. **`MediaService`**（`src/capabilities/media/media.ts`）：`options.config` 改为 `configStore`；包括 agent 日预算在内的读取改为 `current()`；Vision 模型描述与 semaphore 在构造时生成。
7. **`BotCommandService`**（`src/orchestration/bot-commands.ts`）：改为 `configStore`；`/status` 等读取改为 `current()`。
8. **`AdminServer`**（`src/ingress/admin/server.ts`）：`options.config` 改为 `configStore`；默认模型的显示改为 `current()`；listener 参数与 `memoryWarningDays` 在构造时取。
9. **`AgentModelSwitcher`**（`src/platform/model-switch.ts`）：构造参数改为 `(configStore, models)`；`#reference()` 与 `list()` 读 `current()`。

`src/application.ts`：在 `loadConfig` 之后创建 `const configStore = new RuntimeConfigurationStore(loaded)`，传给上面 9 个类。handler 改为 `(invocationId, snapshot, signal) => runtime.run(invocationId, snapshot, signal)`。其它使用 `loaded.config` 的地方保持不变。

### 两个修复

1. **重绑 `thinkingLevel`**：`#runInvocation` 在复用缓存 Agent 时只重新设置了 `agent.state.systemPrompt`、`model`、`tools`，要再加上 `agent.state.thinkingLevel = snapshot.config.agent.thinking_level`（`AgentState.thinkingLevel` 可写，见 `@earendil-works/pi-agent-core` 的 `types.d.ts`）。`#createCachedAgent` 也改为使用快照里的值。
2. **`validateAdditionalTools` 使用在用模型**：把 `this.#model.contextWindow` 改为 `this.#modelSwitcher.model().contextWindow`。`#model` 字段不再有其它用途时一并删除。

## 测试

- 现有测试只改构造方式：多数测试通过 `loadConfig` 得到 `loaded`，用 `new RuntimeConfigurationStore(loaded)` 代替原来传入的 `loaded.config` / `loaded.hash`；少数测试直接传 `config` 和假的 `'hash'`，改为 `new RuntimeConfigurationStore({ config, hash: 'hash' })`；`ContextBuilder` 的测试改为在调用方法时传入 config。直接调用 `runtime.run` 的地方传入 `configStore.beginInvocation()`。涉及约 40 个测试文件，逐个机械修改，不要改动已有断言。
- 新增测试。断言要落在外部可见的结果上（模型请求内容、审计记录、`context_messages` 等），不能只断言内部字段：
  1. 同一个会话连续两次 `run`，第二次传入只有 `thinking_level` 不同的快照，第二次的模型请求使用新的级别。
  2. 两次 `run` 分别传入 `send_max_text_length` 不同的快照，各自的 `send` 按自己快照的上限处理。
  3. 传入 `system_prompt` 不同的快照时，Conversation Context 按 system prompt hash 重建（断言 `context_messages` 与重建审计）。
  4. 用 `/model` 切到 context window 更小的模型后，`validateAdditionalTools` 按新模型的窗口判断。
  5. scheduler 交给 handler 的快照就是转换为 `running` 时 `configStore` 的当前配置。
