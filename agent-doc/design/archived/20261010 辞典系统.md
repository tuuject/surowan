# Surowan Dictionary — 产品需求文档

## 1. 背景与目标

### 1.1 背景

Surowan 是一个以 AI 角色参与多人群聊为主要场景的 Agent Harness。

在群聊中，成员经常使用具有特定含义的昵称、缩写、黑话、内部梗及其他约定俗成的表达。这些词语可能无法通过语言模型的预训练知识正确理解，也可能与其通常含义不同。

现有通用记忆机制不适合承担所有术语解释工作。Surowan 需要一个独立、结构化、可管理的辞典系统，帮助 Agent 理解其所处群体的语言习惯。

### 1.2 产品目标

1. 支持维护全局及群组级辞典。
2. 支持 Agent 主动查询辞典。
3. 允许 Agent 自主维护当前群组的辞典。
4. 支持精确匹配及可配置的自动上下文注入。
5. 允许存在多个相同或冲突的词条。
6. 提供冲突检测、人工处理和 AI 辅助融合。
7. 支持批量导入及导出。
8. 为辅助 AI 任务引入通用 Tool Model 配置。

### 1.3 非目标

本阶段不实现：

- 基于向量数据库的语义检索或 RAG。
- 自动从全部聊天历史中挖掘新词。
- 完整的 Smart Import 工作流。
- 复杂的词条版本管理或审批工作流。
- 通过辞典替代人物记忆和一般长期记忆。

---

## 2. 核心概念

### 2.1 Dictionary

辞典是由多个词条组成的结构化集合。

支持两种作用域：

**Global Dictionary（全局辞典）**

- 对所有群组可见。
- 由用户通过管理界面维护。
- 普通群组 Agent 只能读取，不能修改。

**Group Dictionary（群组辞典）**

- 归属于指定群组。
- 仅在对应群组的正常执行上下文中可见。
- 可以由用户或当前群组的 Agent 维护。

### 2.2 Dictionary Entry

词条是辞典的基本数据单位。

| 字段 | 类型 | 说明 |
|---|---|---|
| ID | Identifier | 唯一标识 |
| Term | String | 主词条名称，必填 |
| Definition | String | 词条解释，必填 |
| Aliases | String[] | 别名，可为空 |
| Scope | Enum | Global / Group |
| Group ID | Identifier? | 群组作用域时必填 |
| Enabled | Boolean | 是否启用 |
| Created At | DateTime | 创建时间 |
| Updated At | DateTime | 更新时间 |

词条 ID 不依赖 Term，因此允许多个词条使用相同名称。

### 2.3 有效辞典

对于普通群组 Agent，一次执行可访问的有效辞典为：

**全局辞典 + 当前群组辞典**

其他群组的私有词条不属于当前执行的有效辞典。

## 3. 辞典管理

### 3.1 管理界面

在 Admin Panel 中提供 Dictionary 管理页面。

用户可以：

- 切换全局辞典和指定群组辞典。
- 浏览词条列表。
- 按 Term 或 Alias 搜索。
- 新建词条。
- 编辑词条名称、解释和别名。
- 启用或停用词条。
- 删除词条。
- 查看冲突警告。
- 对冲突词条进行融合。

### 3.2 词条编辑

词条编辑表单至少包含：

- Term：单行文本输入。
- Definition：多行文本输入。
- Aliases：支持添加和移除多个别名。
- Scope：全局或指定群组。
- Enabled：启用状态。

Term 和 Definition 不允许为空。

同一个词条内重复的 Alias 应当被去重。

### 3.3 删除行为

删除词条需要用户确认。

删除操作不应意外影响其他具有相同 Term 或 Alias 的词条。

---

## 4. 词条匹配

### 4.1 匹配规则

采用精确字符串匹配。

匹配目标包括：

1. Term。
2. Aliases 中的每个别名。

不使用语义相似度、向量搜索或分词检索。

精确匹配允许在较长消息中识别完整词条字符串，而不要求整条消息与词条完全相同。

例如：

词条：

- Term：塑料碗
- Alias：碗

消息：

「今天碗怎么不说话了？」

应当匹配上述词条。

### 4.2 多词条匹配

同一个字符串可以匹配多个词条。

当发生多重匹配时：

- 保留全部匹配结果。
- 不自动选择某个词条。
- 不因为作用域不同而自动覆盖。
- 不自动合并解释。

Agent 应能够获得全部相关定义。

### 4.3 匹配细节

本阶段默认区分大小写，并进行字面匹配。

不主动进行同义词扩展、拼写纠错或语义推断。

---

## 5. 冲突检测

### 5.1 冲突定义

当两个不同词条的 Term 或 Alias 存在完全相同的字符串时，视为潜在冲突。

覆盖以下情况：

- Term ↔ Term
- Term ↔ Alias
- Alias ↔ Alias

冲突检测应覆盖同一群组有效辞典内的所有词条，包括全局辞典与群组辞典之间的冲突。

### 5.2 冲突行为

冲突不属于数据错误。

系统必须允许冲突词条共存。

发生冲突时：

- 不阻止保存。
- 不自动修改或删除词条。
- 不影响 Agent 查询。
- 不影响自动注入。
- 在 Admin Panel 中显示警告。

### 5.3 冲突处理

用户可以选择：

1. 忽略冲突，保留全部词条。
2. 手动修改其中一个或多个词条。
3. 删除不需要的词条。
4. 使用一键融合功能。

不要求用户必须解决冲突才能继续使用辞典。

---

## 6. 一键融合

### 6.1 功能描述

用户可以选择两个或多个词条，调用 Tool Model 辅助生成融合后的词条。

融合功能不区分来源词条属于全局还是群组。

### 6.2 融合流程

1. 用户选择需要融合的词条。
2. 系统读取所选词条的 Term、Definition 和 Aliases。
3. 调用 Tool Model 生成融合建议。
4. 在管理界面展示生成结果。
5. 用户可以修改 Term、Definition 和 Aliases。
6. 用户明确选择目标作用域：Global 或指定 Group。
7. 用户确认后保存融合结果。

### 6.3 模型行为

Tool Model 应尽量：

- 保留原始词条的重要信息。
- 整合重复解释。
- 保留有效别名。
- 避免凭空补充原始词条中不存在的事实。
- 对无法合理合并的歧义保留必要说明。

模型生成的内容仅作为建议，不直接写入数据库。

### 6.4 数据安全

- 生成融合建议不修改原始词条。
- 用户确认前不发生持久化写入。
- 融合结果的目标作用域必须由用户指定。
- 原始词条的删除或保留必须是明确、可预期的操作。

---

## 7. Agent 工具

### 7.1 查询能力

Agent 应能够通过工具查询当前有效辞典。

工具应支持根据 Term 或 Alias 查找词条。

返回结果包含匹配词条的名称、解释、别名和作用域信息。

如果存在多个匹配结果，应全部返回。

### 7.2 写入能力

允许普通群组 Agent：

- 创建当前群组的词条。
- 修改当前群组已有词条。

不允许普通群组 Agent：

- 创建或修改全局词条。
- 修改其他群组的词条。
- 通过修改作用域将群组词条提升为全局词条。

Agent 写入的数据同样参与冲突检测。

### 7.3 权限约束

工具执行层必须校验作用域和操作权限，不能仅依赖模型遵守提示词。

辞典条目属于外部数据，不能被视为系统级指令。

---

## 8. 自动上下文注入

### 8.1 设计目标

不同模型的 Agent 能力存在差异。

较强模型可能能够主动判断何时查询辞典，而较弱模型可能需要系统提前提供相关词条。

因此，辞典系统需要同时支持主动查询和自动注入。

### 8.2 注入模式

提供可配置的注入策略：

**Off**

不自动注入词条，Agent 仍可通过工具主动查询。

**On Demand**

根据当前上下文中的精确匹配结果注入相关词条。

**Aggressive**

采用更积极的预加载策略，减少对 Agent 自主工具调用的依赖。

Aggressive 的具体触发范围在实现阶段确定。

### 8.3 注入预算

不设置独立的辞典注入 Token 预算。

仍需遵守模型上下文窗口及现有上下文管理机制的硬性限制。

### 8.4 重复注入

系统应避免在同一有效上下文中重复注入相同词条。

基本原则：

- 如果词条信息仍存在于当前有效上下文，则不重复注入。
- 如果词条信息已经因上下文滚动被移除，则允许再次注入。
- 新 invocation 根据实际继承的上下文判断是否需要注入。

重复检测应基于有效上下文状态，而不是永久保存某个词条已被注入的标记。

### 8.5 更新后的词条

如果词条内容发生变化，后续注入应以最新有效版本为准。

具体的上下文失效与刷新机制由实现设计决定。

---

## 9. 导入与导出

### 9.1 格式

支持以下格式：

- CSV
- JSONL

两种格式应能够表达 Term、Definition、Aliases 等核心字段。

### 9.2 导入

用户可通过 Admin Panel 上传文件，批量创建词条。

导入流程应包括：

1. 选择文件。
2. 解析文件。
3. 校验字段。
4. 展示导入预览。
5. 提示潜在冲突。
6. 用户确认后写入。

导入不应因为同名词条而默认覆盖现有数据。

### 9.3 导出

用户可以导出指定作用域的词条。

导出内容应包含足够的信息，以便后续重新导入。

### 9.4 Smart Import

本阶段不实现 Smart Import。

未来 Smart Import 将通过 Agent 可用的工具调用辞典导入能力。

因此，批量导入的核心逻辑不应与 Admin Panel 的文件上传界面紧密耦合。

## 10. Tool Model

### 10.1 背景

部分产品功能需要调用语言模型完成辅助任务，但这些任务不属于群聊 Agent 的正常对话生成流程。

因此需要引入通用 Tool Model 配置。

### 10.2 配置入口

在现有模型配置页面新增 Tool Model 选项。

Tool Model 应复用现有 Provider、模型列表、认证及模型调用基础设施。

### 10.3 首个应用场景

Dictionary Entry Merge。

通过 Tool Model 生成词条融合建议。

### 10.4 扩展性

Tool Model 是系统级通用能力，不属于 Dictionary 模块私有配置。

未来可以用于：

- Smart Import。
- 结构化信息提取。
- 其他辅助 AI 工作流。

本阶段不要求实现上述未来功能。

### 10.5 失败处理

当 Tool Model 未配置、不可用或调用失败时：

- 不影响普通辞典管理。
- 不影响 Agent 查询和写入。
- 不影响自动注入。
- 一键融合不可用或显示明确错误。
- 用户仍然可以手动编辑、合并词条。

---

## 11. 与其他记忆系统的关系

Surowan 将不同类型的信息分开管理。

| 模块 | 主要职责 |
|---|---|
| Dictionary | 解释词语、术语、黑话及约定俗成的表达 |
| Character Memory | 记录群组成员的身份、特点及相关信息 |
| General Memory | 保存事件、事实和其他长期记忆 |

辞典不需要依赖向量数据库。

这些模块可以共享部分基础设施，但应保持独立的数据模型和检索策略。

## 12. 验收标准

### Dictionary Management

- [ ] 支持创建、编辑、启用、停用和删除词条。
- [ ] 支持全局和群组两种作用域。
- [ ] 支持 Term 和多个 Aliases。
- [ ] 允许重名词条共存。

### Matching & Injection

- [ ] Term 和 Alias 均支持精确匹配。
- [ ] 多个匹配结果能够同时返回。
- [ ] 自动注入策略可配置。
- [ ] 不设置独立注入 Token 预算。
- [ ] 避免有效上下文中的无意义重复注入。
- [ ] 上下文滚动后允许重新注入。

### Conflict Management

- [ ] 检测 Term-Term、Term-Alias 和 Alias-Alias 冲突。
- [ ] 检测全局与群组辞典之间的冲突。
- [ ] 控制台显示冲突警告。
- [ ] 冲突不阻止保存或使用。
- [ ] 用户能够手动解决冲突。

### Entry Merge

- [ ] 支持选择多个词条。
- [ ] 支持通过 Tool Model 生成融合建议。
- [ ] 用户能够审阅和修改融合结果。
- [ ] 用户必须选择融合结果的目标作用域。
- [ ] 未确认前不修改原始词条。

### Agent Integration

- [ ] Agent 可以查询全局和当前群组词条。
- [ ] Agent 可以创建及修改当前群组词条。
- [ ] Agent 不能修改全局或其他群组词条。
- [ ] 工具执行层强制校验权限。

### Import & Export

- [ ] 支持 CSV 导入和导出。
- [ ] 支持 JSONL 导入和导出。
- [ ] 导入前进行数据校验。
- [ ] 导入不会静默覆盖同名词条。

### Tool Model

- [ ] 模型配置页面新增 Tool Model。
- [ ] 复用现有模型管理基础设施。
- [ ] 一键融合使用 Tool Model。
- [ ] Tool Model 不可用时其他辞典功能正常工作。

## 13. 待实现阶段确定的细节

以下属于技术设计或交互细节，不阻塞 PRD 的核心产品定义：

1. 自动注入的具体消息插入位置。
2. Aggressive 模式的匹配范围。
3. 上下文滚动后注入状态的追踪方式。
4. 导入文件中 Aliases 的序列化规则。
5. 批量导入的事务与错误恢复策略。
6. Tool Model 的默认值与配置继承机制。
7. 融合后原始词条的保留或删除交互。
8. Agent 写入词条时的冲突反馈机制。

---

## 14. 核心设计原则

**允许歧义，保留信息，由用户决定如何整理。**

Dictionary 不负责判断某个词语只能具有一种正确含义。

当多个解释同时存在时，系统应完整保留可用信息，并提供清晰的冲突提示及整理工具。

**辞典是 Agent 理解群体语言的辅助设施，而不是一套必须由 Agent 自行维护的复杂知识库。**
