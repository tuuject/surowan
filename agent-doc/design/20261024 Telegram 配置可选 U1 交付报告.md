## 本单元范围

按 §7 的 U1：配置层 + `config-diff` + 只读 `FileConfig` 的调用方。没有接线连接状态、连接管理器、面板端点或 CLI 变更。

## 主要变更

### 配置 schema 与运行时形状

- `src/platform/config-schema.ts`
  - `telegram` 改为可选；段内仅两处放宽：`token` 可选、`chats` 去掉 `minItems`。段内其余字段保持必填。
  - `admin` 改为必填；`admin.enabled` 改为可选。
- `src/platform/config-resolve.ts`
  - 新增 `TELEGRAM_DEFAULTS` 与 `resolveTelegramSection()`。文件里没有 `telegram` 段时，运行时补 `chats: []`、无 token 和下列默认值；所有默认值只在这一处定义。
- `src/platform/config.ts`
  - `RawConfig.telegram` 仍然总是存在；`token` 在解析后仍可缺省。
  - 新增 `AdminRuntimeConfig`（`enabled` 一定为布尔值）与 `TelegramSectionConfig` 类型别名；`assembleRawConfig` 负责补齐默认值。
- `src/platform/config-semantics.ts`：参与时段、Chat、admin 白名单等校验改走 `resolveTelegramSection()`，无 `telegram` 段时校验空集合。

### 补齐的默认值

| 字段 | 默认值 | 依据 |
| --- | --- | --- |
| `telegram.process_bot_messages` | `false` | 现有示例配置与既有行为；不处理其他 bot 的消息 |
| `telegram.bucket_window_seconds` | `15` | 文档示例与测试 fixture 的既有取值 |
| `telegram.chats` | `[]` | PRD：Chat 允许为空 |
| `telegram.token` | 缺省（停用） | PRD：token 为空即停用 |
| `admin.enabled` | `true` | PRD：缺省视为开启 |

`bucket_window_seconds` 取 15 而不是 0：`idle_grace_seconds` 的默认值仍是 0，两者组合合法；15 与文档示例一致，不会让「无 telegram 段」的部署在升级后改变已有 Playground 行为的时序（Playground 的 policy 本身取 0）。

### diff 与热更新

- `telegram.token` 进入热更新白名单：改 token / 清空 token 不再要求重启，由后续 U3 的连接管理器接管。
- `mergeTelegram()` 现在接受两边都缺少 `telegram` 段：
  - 整个段消失时，热字段（token）立即从 candidate 删除，restart 字段保留到重启；
  - 整个段从无到有时，各字段按白名单独立分类（token 与新增 Chat 是 hot，`process_bot_messages`、`bucket_window_seconds` 等是 restart），candidate 的运行时形状由 `resolveTelegramSection()` 补齐，因此仍可用。
- 由于新增白名单与段缺失逻辑后 `config-diff.ts` 触发仓库 5,000 token 限制，按职责拆成：
  - `src/platform/config-diff-merge.ts`：热更新白名单、分类、字段合并原语、`deepEqual`、`ChangeRecorder`；
  - `src/platform/config-diff-providers.ts`：Provider 与模型列表合并；
  - `src/platform/config-diff.ts`：组装 candidate、telegram/agent/vision/chat 合并。
  - `deepEqual` 的导入方（`src/platform/providers.ts`、`src/ingress/admin/model-health.ts`）已改指向新模块，没有保留 re-export shim。

### `FileConfig` 的只读调用方

以下位置都改为正确处理 `telegram` 段缺失：

- `src/adapters/local-monolith/config.ts`（读取 Chat 的 instructions 文件）
- `src/adapters/local-monolith/config-reload.ts`（`/addchat`、忽略用户、Chat 模型命令）
- `src/ingress/admin/chats-admin.ts`、`admins-route-admin.ts`、`dictionary-route-admin.ts`、`prompts-admin.ts`、`providers-admin-write.ts`
- `src/platform/proactive-reply.ts` 的配置入参类型
- `scripts/seed-dev-data.ts`

### 面板写入时建段

- `src/adapters/local-monolith/config-file.ts`：任何写到 `telegram.*` 以下的编辑，在文件尚无该段时先用 `TELEGRAM_DEFAULTS` + `chats: []` 建段，否则 `chats[0]` 之类的单独编辑会写出 schema 拒绝的文件。规则只实现一处，Chats/Admins/Harness 等写端点自动受益。
- `chats-admin.ts`：删除最后一个 Chat 不再返回 `last_chat_required`（PRD：chats 可以一直为空）。文件仍是合法的空白名单，`telegram` 段本身不会因删 Chat 消失。

## 与交接说明 / PRD 的出入

没有与 PRD 冲突的实现选择。需要 review 注意的现状说明：

1. **Doctor 仍是过渡状态**：没有 token 时 `doctor` 现在会报 `Telegram is disabled: no Bot token is configured`。这是为了让 U1 通过类型检查的临时处理，U8 会按 §4.10 改成「报告 Telegram 停用并跳过 Telegram 探针」。
2. **`serve` 仍未改造**：U1 只加了「token 不存在时不构造 Bot」的判空，让无 `telegram` 段的配置能通过启动装配；Scheduler 对 Telegram 工作的放行、连接状态与停止流程仍按 U2/U3 计划处理。U1 的单测不覆盖「无 token 但非 playground-only 的长运行行为」。
3. **`admin.enabled` 的运行时归一化**：`RawConfig.admin.enabled` 在 `assembleRawConfig` 里归一为布尔值，因此 `serve`/面板/Inspection 看到的是 `true`/`false`；文件层仍保留「字段缺省」。
4. **新增 Chat 仍按现有规则为 hot**；删除 Chat 仍是 restart，未在本任务里改动（§5）。
