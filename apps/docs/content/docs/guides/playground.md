# 使用 Playground 虚拟群聊

Playground 是 Admin Panel 内置的虚拟群聊沙盒。房间里的输入走的是与真实群聊同一套 Scheduler、Agent Runtime 和模型配置，但所有输出只回到虚拟房间，不会发往 Telegram，也不会触发 Alarm、MCP、辞典写入或全局休眠。它适合在不动真实群的情况下试人格、看回复、验工具行为。

## 打开页面

1. 启用 Admin Panel（`admin.enabled: true`）并登录。
2. 在侧栏进入 **虚拟群聊**（`/playground`）。

也可以完全不接 Telegram 运行：`node src/cli.ts serve --config <config.jsonc> --playground-only` 只装配 Playground 宿主，不解析 Telegram token、不创建 Bot、不做任何 Telegram 网络请求。注意此时配置里的 `telegram` 段仍是必需的结构占位（不会被当作房间配置），且 `admin.enabled` 必须为真——面板是房间唯一的写入口。

## 建房与身份

- **新建房间**：填房间名称，可一并填写初始身份（逗号分隔）。新房间默认开启 Hold，生图默认关闭。
- **身份**：每个房间有自己的身份列表，名称允许重复（用于模拟同名群友），每个身份彼此独立。发送消息前先选择「发送身份」。身份分成员与管理员两种角色，仅作展示区分。
- 房间与身份的创建按请求 key 幂等：网络断线后重试同一操作不会产生第二个房间或身份。

## Hold 与 Release

房间里的每条消息都会先进入 **Hold**：只进入「待处理」队列，不会启动任何模型调用，已经排队或运行中的运行也不受影响。Release 之后再发的消息会重新打开 Hold，没有「发了就自动运行」的模式。

- 点 **Release** 把当前全部待处理消息封成一个批次，排队一次真实运行；一次 Release 只结算这一批。没有待处理消息时 Release 只关闭 Hold，不产生调用；房间不在 Hold 时 Release 会被拒绝。
- Release 后输入按接纳顺序进入运行；如果上一个运行还在跑，新的批次排队等待，同一房间同时最多一个运行。
- Hold 期间攒下的输入若一直不 Release，会随在线数据保留期（`retention.online_days`）过期，页面上会显示已过期的条数。
- 运行开始前排队超过五分钟的批次会被判为过期失败，不会静默重放。

## 发消息与图片

- 在选定的身份下输入文本发送；可以对一条消息选 **回复** 再发，模型看到的引用关系与真实群一致。
- 可附加静态图片：仅 JPEG / PNG / WebP，单张不超过 10 MiB、不超过 4000 万像素，动图（APNG、动画 WebP/GIF）会被拒绝。拒绝原因来自服务端校验，页面会保留草稿。
- 上传后未挂到消息、且超过一小时的暂存图片，会在之后的房间写入时顺带清理（每小时最多一次）；房间没有新的写入时不会清理。
- 已发送的图片进入模型上下文，模型也可用 `read_image` 按引用细看（需要配置 Vision）。

## 运行、输出与重试

- **运行** 列表显示每次 Release 产生的运行：排队中、运行中、已完成、失败、已中止、结果未知，以及 token 用量与费用。运行完成但模型选择沉默时显示「已结束/未发送」，不伪造回复。
- 每次运行旁的 **审计** 链接打开与 Telegram 群共用的 Invocation 详情页，能看到工具调用、模型请求、房间发送与冻结上下文。Invocation 列表里房间运行标注为 Playground，可用宿主过滤只看房间。
- Bot 的输出以房间消息形式出现在时间线，带发送状态（已送达等）；普通 assistant 私有文本不会显示为群消息。
- 失败或中止的运行可点 **重试**：只有「零注入、零模型请求、零副作用」且已终止的尝试才允许重试；同一房间已有更晚的 Release 时会被拒绝。不满足条件的运行页面会给出原因。

## 生图开关（真实计费）

- 每个房间的 **图片生成** 默认关闭。开启后该房间的模型可以真实调用生图服务，**会产生费用**；开关记录操作者与时间。
- 开关本身不校验配置：要真正生效，还需要全局 `image` 配置已就绪，否则开启后也无法生图。关闭只阻止新的提交，已经受理的生成会继续完成并把成品回执送回该房间。
- 生成原件进入图片归档并随备份保留；房间里展示的副本按本地资产管理。

## 用量、记忆与数据边界

- Playground 的 Agent 与 Vision 用量记在独立的 `playground` 计量域，复用同一套上限配置，但不会挤占 Telegram 会话的账目；Usage 页可区分查看。
- 房间有自己的 Conversation 记忆，与其它房间、Telegram 会话完全隔离。
- 房间消息、运行与审计随 `retention.online_days` 清理；台账与回执不随消息删除而消失。
- 备份覆盖房间的本地图片资产，恢复后仍可读取。

## 常见误区

- Playground 不是 mock：Release 触发的是真实模型调用，同样计费；想省钱就别 Release。
- Hold 不是暂停运行：它只让新输入停在待处理队列里，不取消已排队、运行中的运行或已授权的生图。
- 房间不是 Telegram 群：没有 @、Topic、Sticker、Alarm、MCP 或辞典写入；页面上的身份不会出现在任何真实聊天里。
- 「结果未知」不是失败：进程中断时运行可能已产生真实副作用，重试守卫会拒绝盲目重放，请先核对时间线与审计。
