# 用循环闹钟安排定时任务

循环闹钟让 Bot 按时间表主动做事，例如每天早上八点在群里问候，或每天下午六点整理一份简报。每个循环闹钟由三部分组成：发到哪个会话、什么时候触发、触发时交给 Bot 的提示词。

循环闹钟只能由管理员在 Admin Panel 创建和修改。群友不能申请，Bot 自己也不能创建、查看或删除循环闹钟。提示词被当作你下达的可信指令：Bot 会像你在群里提出要求一样去执行，但它仍然只能用自己本来就有的工具，提示词不会给它新的权限。

它与 Bot 自己的「稍后提醒」（Alarm）不同：Alarm 是群友让 Bot 记下的一次性提醒，由 Bot 在对话中创建；循环闹钟是管理员设定的周期任务。

## 创建循环闹钟

1. 登录 Admin Panel，进入 **Recurring alarms**（循环闹钟）。
2. 点击 **New recurring alarm**。
3. 填写标题。标题只在面板里显示，用来区分不同的闹钟，Bot 看不到它。
4. 选择目标。可选的是已配置、Bot 已经见过的 Telegram Chat，配置了 Topic 白名单的群按 Topic 列出；Playground 房间也能选，方便在不打扰真实群聊的情况下试效果。暂时无法接收消息的目标（例如已暂停的 Chat）会标出原因，不能选。保存后目标不能更换。
5. 设定时区和执行周期（见下一节），写好提示词，确认是否启用，然后创建。

每个会话最多 20 个循环闹钟。

## 设定执行周期

执行周期可以用两种方式编辑，它们是同一份规则的两种视图：

- **规则**：每条规则有分、时、日、月、星期五个字段，每个字段选「每」或「第」。「每」后面留空表示每一个单位都触发，填 N 表示每隔 N 个单位；「第」后面填具体的值，多个值用逗号分隔，例如分钟填 `0,30` 表示整点和半点。星期直接勾选。
- **Cron**：每行一条标准 5 段 cron 表达式：`分 时 日 月 星期`，例如 `0 8 * * *` 是每天 8:00，`30 9 * * 1-5` 是工作日 9:30。星期 `0` 是周日。

可以添加多条规则，任意一条命中就触发。同一条规则里同时限定了「日」和「星期」时，两者满足其一即可，这和常见的 cron 一致。不支持秒、年，也不支持 `L`、`W`、`#`、`?` 这类扩展写法。

用 Cron 写了规则控件表示不了的写法（例如范围 `1-5` 或月份缩写）后，只能继续用 Cron 编辑。

编辑时，下方会预览接下来的 5 次触发时间，按所选时区显示。两次触发间隔小于 5 分钟时会给出提醒，但仍然可以保存。

时区填 IANA 名称，例如 `Asia/Shanghai`，新建时默认是全局时区。每个循环闹钟记住自己的时区，以后修改全局时区不会让已有的「早上八点」跟着移动。

## 到点时会发生什么

- 目标会话里 Bot 正在运行时，这次任务会在当前工具链结束后并入；否则新开一次运行。
- 它不占每日 Token 预算，Bot 处于睡眠时段时也照常执行。Playground 房间仍按房间自己的预算规则。
- Bot 收到的是你的提示词和这次的计划时间，由它决定怎么完成、发什么消息。和平常一样，只有它真的调用发送工具时消息才会出现在群里。

以下情况这一次会被跳过，并在触发记录里写明原因，循环闹钟本身保留，之后照常触发：

- 服务停机或 Telegram 断线，恢复时已经比计划时间晚了 30 分钟以上。晚得不多时，期间错过的多次只补发一次。
- Chat 已暂停、已从配置里移除，Topic 不在白名单里，或 Agent 没有配置完整。
- 上一次触发还没投递完。

## 立即执行一次

每一行的 **Run now**（立即执行）按钮会用已保存的提示词马上执行一次，适合调提示词时看效果。它和到点触发走同一条路径，Bot 看到的内容也完全一样；不会改变执行周期，停用状态下也能用。上一次还没投递完时不能再次立即执行。

## 编辑、停用与删除

- 编辑时修改执行周期或时区，下次触发时间会从当前时间重新计算；只改提示词，影响之后的触发。
- 列表里的开关可以停用或启用。停用后保留执行周期，但不会再触发；还没开始投递的那一次会被取消。
- 删除会移除执行周期和触发记录，同样取消还没投递的那一次。

点击 **Details** 可以查看最近 50 次触发：计划时间、来源（定时或手动）、结果，以及处理它的那次运行。

## 用 API key 管理

API key 也能管理循环闹钟（`surowan-utils` 的 `recurring-alarm` 命令或 MCP 工具）。查看与预览只需要读权限；新建、编辑和立即执行会让 Bot 在无人值守时调用模型，需要同时具备写权限和付费操作权限；删除只需要写权限。
