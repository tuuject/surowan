# 密钥（Keychain）

配置里的 Token、API key 都不写明文：文件里写 `{ "jar": "<name>" }` 这样的引用，明文放在配置文件同目录的 `key.json`（keychain）里。每个条目有一个稳定、可读的名字，同一把密钥可以被多处使用，轮换时只改一处。在面板 **System → 密钥**（`/keychain`）页面管理这些条目；任何地方都不显示密钥的值。

## 条目列表

列表显示每个条目的 **Name**、**Created** 与 **Used by**（配置文件里引用它的路径）：

- **Used by** 由配置文件反推，不单独保存；被忽略的配置段（例如暂时损坏的 `image` 段）里的引用也算数。
- 运行中的配置仍在使用、但文件里已经改掉的条目（例如待重启的 `telegram.token` 或 MCP Server）会显示「仅运行中的配置」。
- **Values are never shown**：任何页面、任何接口都不返回密钥的值、片段或摘要。

## 新建条目

点 **New entry**，填名字（1–64 个字母、数字、`_` 或 `-`）与值。可以先建一把暂时没人用的密钥，再到使用处引用它。重名直接报冲突，不会替你改名。

## 轮换

点条目行的 **Rotate** 输入新值。轮换在原条目上替换值并保留创建时间；成功后立即触发一次配置应用：

- Provider 连接检测到值变化就重建，下一次会话用新密钥；进行中的会话用它启动时的快照。
- 被多个地方共用的条目，轮换对所有使用处同时生效。

手工改 `key.json` 里的值同样会在下一次配置应用时被识别，不需要换名字或重启。

## 删除与清理

- 点行内 **Delete** 删除单个条目；只有**未被任何地方引用**（配置文件与运行中的配置都不引用）的条目可以删除。
- **Purge orphans** 一键清理孤儿条目：确认弹窗列出将被删除的名字，服务端只删除其中此刻仍是孤儿的条目；确认与执行之间状态变化时，新出现的引用不会被删掉。清理不可撤销。
- 配置文件无法解析时，删除与清理都会被拒绝，而不是按残缺的引用集合冒险。

## 外部引用

`{ "env": "X" }` 与 `{ "command": [...] }` 两种引用不迁移、不展示值：列表只显示用在哪、是哪一种与环境变量名，外部命令的参数不展示。它们的轮换语义不变（环境变量要重启，外部命令在引用变化或重启时重新执行）；面板不能新建这两种引用，需要的话手写配置文件。

## 录入密钥的通用方式

Provider、Telegram、联网搜索与图片设置页的密钥输入框都是同一个控件：**填新密钥**（条目名按使用处自动推导，可修改）或**选用已有条目**（来自本页的列表）。密钥不进配置文件；被替换下来的条目不会自动删除，等这里的显式清理。
