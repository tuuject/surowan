# 接入 MCP 服务器

出站 MCP 让 Bot 调用外部 MCP Server 的工具。Server 由管理员显式配置，可用 stdio（运行宿主机上的命令）或 Streamable HTTP，模型只在这里被允许的 Server 与 Tool 范围内活动。

每一次调用都受 allowlist、只读策略、超时与大小限制约束，并留下审计记录，任何配置都不会给模型新的授权。

## 在管理面板添加与管理 HTTP MCP 服务器

打开左侧栏 **机器人 → MCP 服务器（MCP servers）**：

![MCP 服务器页：状态、渐进式暴露与技能列表](__DOCS_BASE__/screenshots/tools/mcp-servers.zh-CN.light.png)

页面显示每个 Server 的实时状态（**就绪** / **连接中** / **不可用** / **无实时状态**，含错误码）、连接摘要、它发现过的全部工具（含被工具选择隐藏的），以及使用情况（哪些会话显式绑定、哪些会话靠继承使用）。

添加一台远程 **Streamable HTTP** MCP 服务器只需五步，保存后就开始在后台连接，不需要重启服务：

1. 点右上角 **添加服务器**。
2. 填写连接信息：
   - **别名**：字母开头，只能使用字母、数字、下划线或短横线，最长 64 个字符。模型看到的工具名形如 `别名__工具`。
   - **URL**：外部服务器的 Streamable HTTP 端点，不允许带用户名/密码或 `#` 片段，重定向会被一律拒绝。
   - **请求头**（可选）：如果服务端需要鉴权头（如 `Authorization`），逐条添加名称与值，支持填入新密钥（自动存进 `key.json`）、选用已有 **密钥**（Keychain）条目，或使用外部引用。
3. 配置工具与上限：
   - **工具选择**：选 **全部工具** 时填一份默认策略（是否 **只读**、**超时（秒）**）；选 **选定工具** 时逐个添加工具名并为每个工具分别设只读标记与超时。
   - **请求体上限（字节）**（1–1048576）与 **结果上限（字节）**（1–32768）。
4. 配置呈现与技能：
   - **暴露方式**：选 **直接暴露** 或 **渐进式暴露**（区别见下一节）。选渐进式时建议填写 **描述**（最多 1000 字）；也可以先保存并等状态变为 **就绪** 后再点编辑里的 **用工具模型起草**。
   - **向模型提供技能**：决定模型能否用 `read` 读取该服务器发布的 Skill，默认开启。
5. 点保存后等待几秒刷新状态，看到 **就绪** 且 **已发现的工具** 列出工具即表示接入完成。如果需要限制只在特定群使用，再到 **Telegram → 会话** 给对应群配置 **MCP 服务器** 绑定。

编辑与删除边界：

- **编辑**：HTTP Server 可以改 URL、请求头、工具选择、上限、策略、暴露方式、描述与技能开关。stdio Server 只能改工具选择、上限、策略、暴露方式、描述与技能开关，它的命令、参数、环境变量与传输方式在面板里保持只读。
- **删除**要求先解绑：还有会话显式绑定该 Server 时会返回绑定它的会话列表。不写 `mcp` 字段的会话继承全部 Server，删除后它们自动失去这个来源。

## 配置 stdio MCP 服务器

使用 `stdio` 传输的 MCP Server 需要由塑料碗在运行环境中直接拉起本地子进程，通过标准输入输出通信。它不能通过管理面板新建，需要登录服务器直接编辑 `config.jsonc`：

1. 如果该 MCP Server 需要 API Key 或令牌，先到面板 **系统 → 密钥**（Keychain）新建一个命名条目（例如 `mcp_fs_token`），避免在配置文件里写明文。
2. 编辑服务器上的 `config.jsonc`，在 `mcp.servers` 中追加一条 `transport: "stdio"` 配置：

```jsonc
{
  "mcp": {
    "servers": [
      {
        "alias": "fs",
        "transport": "stdio",
        "command": ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/data/notes"],
        "env": { "LOG_LEVEL": { "jar": "mcp_fs_log" } },
        "tools": ["read_file", "list_directory"],
        "payload_max_bytes": 65536,
        "result_max_bytes": 32768,
        "tool_policies": [
          { "name": "read_file", "read_only": true, "timeout_seconds": 30 },
          { "name": "list_directory", "read_only": true, "timeout_seconds": 15 }
        ]
      }
    ]
  }
}
```

- `command` 是参数数组：第一项是可执行程序，后面是逐个参数。它不经过 shell，不会解析管道、重定向或通配符。
- `env` 里的每个值都是 SecretRef（如 `{ "jar": "..." }` 或 `{ "env": "..." }`），与受限的默认环境变量合并后传给子进程。
- **Docker 部署注意**：官方镜像内置 **Node.js 24（含 `npx`）与 Python 3**，且已经将 npm 缓存配置到可写卷 `/data/.npm-cache`，因此常见的 `npx -y <包名>` MCP Server 在容器内可以直接启动并复用缓存。如果要让 stdio Server 访问宿主机上的文件目录，需先在 `docker-compose.yml` 里把该目录挂载进容器（建议按需使用 `:ro` 只读挂载），再把容器内路径写进 `command`。若依赖镜像里没有的运行环境（例如 `uvx` 或自定义二进制），需基于官方镜像自行扩展 `Dockerfile`，或改用宿主机部署。
3. 改完后先用 `check-config` 离线校验配置无误，再到面板 **设置** 页点应用配置（或调用 `POST /api/config/apply`）即可生效，无需重启服务。生效后这台 stdio 服务器会出现在 **MCP 服务器** 列表里，之后可以在面板里直接调整它的工具选择、上限、策略、暴露方式、描述与技能开关。

## 为什么不能在管理面板设置 stdio MCP 服务器

这条限制是刻意设立的安全边界（并非遗漏了表单）：

1. **stdio 的本质是宿主机命令执行**：`command`、`args` 与 `env` 会让塑料碗进程在服务器（或容器）内直接启动任意可执行程序，并以服务进程自身的权限运行，能够访问配置目录、数据库、媒体缓存和挂载卷。
2. **避免管理面与外部 Agent 提权**：管理面板的 `/api/mcp-servers` 写接口不仅服务浏览器会话，也开放给持有 `read_write` 或 `all` 权限的 API 密钥、已配对客户端与本地 Coding Agent。如果允许通过面板表单或 HTTP API 提交任意 `command`，任何拿到面板登录态或写权限凭据的一方（包括可能遭遇提示词注入的外部 Agent）都能借此在服务器上执行任意命令，直接击穿「凭据与宿主机执行能力分离」的信任边界。
3. **把代码执行面留在服务器文件权限里**：因此只有能直接登录服务器、且拥有 `0600` 权限 `config.jsonc` 写入权的运维人员，才可以新增或修改 stdio 服务器的命令、参数与环境变量。管理面板和 API 只负责安全范围内的运行时治理（工具筛选、策略、上限、暴露方式、描述与技能开关），连接字段在面板里始终只读。

## 直接暴露与渐进式暴露

每个 Server 可以单独选择**暴露方式**：

- **直接暴露（Direct，默认）**：每个工具都以 `别名__工具` 作为独立工具交给模型，每次请求都带上完整定义。
- **渐进式暴露（Progressive）**：这个 Server 的工具不进入工具列表。模型只看到一个 `mcp` 工具，它的说明里列出所有渐进式 Server 的别名、工具数量与描述，模型需要时用 `mcp` 的 `search` 找工具（中英文都可以搜）、`help` 读完整说明与参数，再用 `call` 调用。

工具多的 Server 适合渐进式，所有渐进式 Server 加起来只占工具列表里的一个位置，不会让每次请求都背着几十份工具定义。代价是模型多一次查找，而且它一开始只能靠**描述**判断这个 Server 能不能帮上忙，所以描述要写好（最长 1000 字）。没写描述时模型只能看到几个工具名，**警告（Warnings）** 页会显示 `mcp_description_missing` 提醒。

描述可以手写，也可以让工具模型根据 Server 公布的工具起草：点「用工具模型起草」。起草是一次**计费**的工具模型调用，结果只是草稿，只会填进输入框，确认并保存后才会写入。

渐进式不放宽任何权限，`mcp` 只能找到并调用这个会话本来就能用的工具（按会话绑定照常收窄），调用走与直接暴露相同的参数校验、只读策略、超时、大小限制与审计。审计里会有两条记录：外层的 `mcp`，以及真正被调用的 `别名__工具`。

## Server 发布的 Skill

支持「MCP with Skills」扩展的 Server 可以同时发布 Skill（说明如何使用它的工具的文档）。每次连接后会发现这些 Skill，并逐个校验文件内容、大小与摘要，校验不通过的直接丢弃，不影响该 Server 的工具。

模型用 `read` 读取这些文档（`mcp-skill://`），范围只限这个会话本来就能用到的 Server。**它们来自外部 Server**，只能说明如何使用该 Server 的工具，不能覆盖 Tool 约束或授权规则。

每个 Server 有一个**向模型提供技能**开关，省略即开启。关掉后模型读不到它的 Skill，修改它不会重连 Server，下一次运行生效。

## 后台建连、降级与恢复

启动**不会**因为某个 Server 连不上而等待或失败。每个 Server 都在后台连接，连不上或校验不通过的实例显示为**不可用**并按退避自动重试，不影响其他 Server，也不耽误启动或这次保存生效。

只有**就绪**的 Server 会把工具交给模型。不可达期间，模型从下一次运行起就看不到它的工具，恢复后自动回来。不可用期间**警告（Warnings）** 页显示 `mcp_server_unavailable` 警告（连接中不告警）。

## 改动如何生效，以及按会话绑定

`mcp.servers` 与每个会话的 `mcp` 改完都不需要重启。在 **设置（Settings）** 点应用配置或任何一次面板保存之后，新增的 Server 会被连接、删除的会被关闭、改过字段的会被替换，没改的保持连接。

改变某个会话能用的工具（删掉绑定、换工具列表、改策略，或它用的 Server 被改）时，这个会话正在进行的运行会被**停下、上下文被重建、然后自动续跑一次**。模型看到的是新的聊天记录，会被告知这次是运营者改了 MCP 配置，并收到被停下时结果未知的 MCP 工具名，避免重复副作用。只是新增 Server 或加宽工具列表不会打断正在跑的对话。只改暴露方式或描述也不会重连 Server、不打断任何对话，下一次运行起按新方式交给模型。

按会话绑定在 **会话（Chats）** 页每行的 **MCP servers** 入口设置：

- **继承全部**（不写 `mcp` 字段）：拿到全部 Server 与它们自己的设置。
- **完全关闭**（空数组）：这个会话没有任何 MCP 工具。
- **显式绑定**：挑选 Server 并收窄工具，可以给某个工具在这个会话里单独指定只读策略与超时。

绑定只收窄，不改连接，命令、URL、环境变量与 Header 仍属于 Server。需要两种连接就配两个别名。Playground 房间永远没有 MCP 工具。

配置字段见[外部 MCP 配置](../configuration/mcp.md)与 [`mcp` 字段参考](../configuration/fields-mcp.md)，按会话的字段见 [Telegram 配置](../configuration/telegram.md)与 [`telegram` 字段参考](../configuration/fields-telegram.md)。

## 只读文档与外部工具的区别

「扩展」在这个项目里有严格的边界，不要混淆：

- **System Skills** 是随版本发布的**只读**说明文档，教模型怎么使用内置功能，模型需要时才去读。Skill 是说明书，不是权限文件，不能绕过任何工具限制、allowlist、预算或发送规则。
- **内置插件**（网页读取、网络搜索与其七家服务商、图片生成、Alarm、辞典）随版本一起发布，只能通过配置启用或调整，没有插件市场。
- **出站 MCP** 是唯一由管理员接入的外部工具来源，且必须显式配置、经过 allowlist、只读策略、超时与大小限制。
- 当前**没有** Skill 上传、自行安装插件或第三方市场入口。

## 常见误区

- 渐进式暴露不改变权限，只是换了一种发现方式。
- 「模型看到了工具名」不等于「调用成功」，去**运行记录（Tool sessions）** 里看具体调用与结果。
