# 你的第一只 Bot

这一页把前面试好的人设接进真实平台。真实平台目前只有 Telegram。

**前提**：面板能登录、主模型能正常回复、人格已经保存。没试过虚拟群聊也没关系，但模型必须可用——见[接入和更换模型](models.md)。

## 1. 在 BotFather 建 Bot

1. 在 Telegram 里打开 [@BotFather](https://t.me/BotFather)，发送 `/newbot`。
2. 按提示填写显示名，再填一个以 `bot` 结尾的用户名，例如 `my_surowan_bot`。
3. 记下它返回的 Token，形如 `123456:ABC-DEF…`。

Token 就是这只 Bot 的全部权限。不要把它贴进聊天、截图、Issue 或交给任何「帮你部署」的机器人；除了下面的面板输入框，不要放到别处。

## 2. 把 Token 存进面板

打开 **Telegram** 页：

![Telegram 页：尚未配置 Token](__DOCS_BASE__/screenshots/first-bot/telegram-token-empty.zh-CN.light.png)

1. 在 **机器人 Token** 卡片里，把 Token 粘进 **新的机器人 Token**。
2. **条目名** 默认是 `telegram`，可以改。Token 存在 Keychain 里，`config.jsonc` 只写条目名，不写明文。
3. 点 **保存 Token**。页面会立刻应用，不需要重启。

保存成功后，**连接** 卡片显示 **状态：正常**、Bot 的 `@用户名` 与数字 ID，`自` 是连接建立的时间。如果状态是 **配置异常** 并写着「Token 被拒绝」，说明 Token 复制错了或被撤销；写着「这个 Token 正被其他进程使用」，说明同一只 Bot 还有另一个实例在轮询，先去关掉那一个。

![Token 生效后连接状态为「正常」](__DOCS_BASE__/screenshots/first-bot/telegram-connected.zh-CN.light.png)

第一次保存会在配置文件里创建整个 `telegram` 段，并带上默认的消息批次时间：最短等待 15 秒、不因新消息延长、最长等于最短。

## 3. 让它在群里能看见消息

私聊消息 Bot 一定收得到。群里受 Telegram 自己的隐私模式限制：**默认只收到以命令、@ 或回复形式指向它的消息**，群友的普通聊天不会送到 Bot。

要让它看见普通消息，二选一：

- 在 BotFather 里对这只 Bot 执行 `/setprivacy`，选择 **Disable**；
- 或者把 Bot 设为该群的管理员。

两种方式都由 Telegram 决定投递范围，与塑料碗的配置无关；改完在群里用普通成员账号随便说一句话验证。注意：即使 Telegram 把消息送到了，塑料碗仍只处理 `telegram.chats` 里允许的会话——下一步就是加进去。

## 4. 允许一个会话

两种方法，效果一样，都是把会话写进 `telegram.chats` 并立即生效。那一行能写哪些字段，见 [`telegram` 字段参考](../configuration/fields-telegram.md)。

**方法一：让 Bot 自己加。** 先把你的数字 Telegram 用户 ID 加到 **机器人管理员**（同样在这一页的 Telegram 分组），然后在目标群里以你的账号发送：

```text
/allowlist
```

它会把当前这个群加进白名单并热应用，不需要知道会话 ID。`/allowlist` 是唯一能在尚未允许的会话里执行的命令，且只有机器人管理员能用。

还不知道自己的数字用户 ID？在还没有任何允许的会话时，塑料碗无法替你显示它（`/whoami` 只在 Bot 会回应的会话里可用），可以先向任意一个查询 Telegram ID 的 Bot（例如 @userinfobot）发一条消息获取。

**方法二：在面板里输入。**

1. 打开 **会话**（页面标题是 **会话白名单**），点 **添加会话**。
2. 填 **Telegram 会话 ID**：群组是负数，私聊是正数。数字不能为 0。
3. 要限定 Forum Topic，可以在 **话题 ID** 里填允许的话题；留空表示允许全部话题。
4. 保存。

会话 ID 在 Telegram 客户端里不直接显示：私聊的会话 ID 就是对方（或你自己）的数字用户 ID，`/whoami` 会在 Bot 能回答的会话里直接报出来；群组用上面的 `/allowlist` 最省事。已经加进白名单的会话，ID 会直接显示在 **会话** 页那一行下面，方便你核对。

![会话页：两个已允许的会话](__DOCS_BASE__/screenshots/first-bot/chat-allowlist.zh-CN.light.png)

## 5. 用 `/help` 验证

在刚允许的会话里发送：

```text
/help
```

Bot 会按你在该会话里的权限列出可用命令，一行一条。命令由运行时直接回答，不交给模型，也不作为聊天记录进入上下文。在未加入白名单的会话里发送 `/help` 不会有任何回复——如果你没收到任何东西，先回到第 4 步。

## 6. 第一次真实对话

1. 在群里发一条普通的、值得接话的消息，例如一个具体的问题。
2. 等一小会儿：Bot 不会逐条回复，而是把一段时间内的消息攒成一批。默认最短等待 15 秒，可以在 **Telegram → 消息批次** 里改，保存后从下一个批次开始生效。
3. 看结果。模型可以选择接话，也可以保持沉默——沉默是正常结果，不代表出错。

要确认它到底做了什么，打开 **运行记录**：一次运行会列出工具调用、模型调用与发送结果。这里能区分「根本没触发」「触发但模型决定不说」和「说了但发送失败」。

## 7. 虚拟群聊里能跑，真实群里没反应？

按顺序排查，多数问题在第一步或第二步：

1. **会话允许了吗？** 看 **会话** 页有没有这一行。
2. **Bot 收到消息了吗？** 群里的隐私模式是否还开着，或者机器人是否是管理员。
3. **触发了吗？** 参与时段、`仅 /ask 唤起`、被忽略名单都会挡下普通消息。
4. **模型可用吗？** 回到 **模型** 页确认主模型，供应商页点 **测试**。

详细的证据链与判定方式见[排查启动失败和不回复](troubleshooting.md)，会话级规则见[为不同群和话题设置边界](chats.md)。
