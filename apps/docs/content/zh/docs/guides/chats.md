# 为不同群和话题设置边界

塑料碗只在 `telegram.chats` 列出的会话里工作。全局段是默认值，`telegram.chats[]` 的每一项是某个会话的覆盖：没写的字段继续继承全局，写了的字段只在那个会话生效。

Chat 与 Forum Topic 是两个层次：Topic 继承所属 Chat 的全部设置（模型、参与策略、MCP 绑定都一样），但**对话上下文按 Chat + Topic 分开**。所以同一个群里不同话题的聊天互不可见，设置却改一处就一起变。

## 允许范围：哪些会话会被处理

- 会话必须在 `telegram.chats` 里。即使 Telegram 已经把消息投给 Bot，不在名单里的会话也不会被处理。
- 不写 `topic_ids` 时允许该会话的普通消息和全部 Topic；写入非空列表时，只允许列出的正整数 Topic ID。
- 会话 ID 必须唯一且非零：私聊为正数，群与 Supergroup 为负数。
- 附加指令、模型覆盖、参与策略、忽略名单、群聊记忆、MCP 绑定都属于整个 Chat，所有 Topic 共用；只有对话上下文和注意力窗口按 Topic 分开。

在面板 **会话**（Chats）页点「添加会话」，填 Telegram 会话 ID 和需要的话题 ID 列表即可。面板里新增会话是热更新的，保存后立即生效。

## 会话页能改什么

**会话**页每一行末尾的「更多操作」菜单按用途分组：

- **会话设置**：「编辑活跃时间」「编辑主动回复概率」「编辑入场闸门」「编辑群聊记忆」。
- **MCP 服务器**：给这个会话绑定外部 MCP 服务器并收窄可调用的工具。
- **打开相关页面**：带 `?chat=<会话 ID>` 跳到提示词、辞典、记忆、群聊记忆、消息、运行记录、提醒等页面，列表直接就筛选到这个会话。
- **删除**：移除会话并删除它的数据，详见下文。

「状态」列说明改动有没有生效：「生效中」表示保存的值正在运行；「有待生效更改」表示改动只写进了文件，还需要重启（典型的是话题范围这类字段）；「待添加」「待删除」表示文件与正在运行的配置不一致。

## 每个会话的模型与思考强度

不写 `provider`、`model` 和 `thinking_level` 时，这个会话用全局模型。要覆盖就在会话里写它们：

- `provider` 与 `model` 必须成对出现，模型必须在该 Provider 的 `models` 里并且支持文本输入。
- 只写 `thinking_level` 表示沿用全局模型、只改思考强度；思考强度必须是当前模型支持的档位之一。

```jsonc
{
  "telegram": {
    "chats": [
      {
        "id": -1001234567890,
        "topic_ids": [100, 200],
        "timezone": "Asia/Tokyo",
        "provider": "gateway",
        "model": "replace-with-your-text-and-image-model",
        "thinking_level": "off",
        "ignored_user_ids": [123456789],
        "participation": {
          "active_windows": [
            { "start": "19:00", "end": "24:00" },
            { "start": "22:00", "end": "01:00", "days": [5, 6] }
          ],
          "trigger_keywords": ["值班"],
          "attention_window_seconds": 600
        }
      }
    ]
  }
}
```

在面板里换模型时，如果这个会话还有正在用旧模型的运行，页面会先确认：确认后这些运行立即终止，它们正在处理的那一批不会再得到回复、也不会重新处理，之前委派的任务不受影响，群友之后的消息马上由新模型处理；取消则什么都不保存。新模型直接沿用现有上下文。只改思考强度不会终止任何运行。

群管理员也可以用命令改：`/model 序号` 写本群模型覆盖、`/model default` 恢复跟随全局；`/effort 级别` 只改思考强度、`/effort default` 恢复继承。命令的效果相同，但不会弹确认框，回执会说明终止了几个运行。命令细节见 [Telegram 命令](../developer/telegram-commands.md)。

## 每个会话的附加指令

会话附加指令写在 **提示词**（Prompts）页：左栏选「会话 <id>」范围，写入后第一次保存会自动创建文件并把 `telegram.chats[].instructions_file` 指向它。它叠加在全局人格之上，不是替换。提示词改动是热更新，从下一次运行起生效。

## 时区

会话的 `timezone` 决定这个会话的活跃时段按哪个本地时间解释；不写时用顶层 `timezone`。面板只显示当前时区（「按 Asia/Tokyo 显示，现在 …」），不能在页面里改：它是配置文件字段，修改后需要重启才生效。

## 忽略名单与自助命令

`ignored_user_ids` 是这个会话不再理会的成员。名单里的成员发来的普通消息、编辑和其他命令都不会进入模型，但消息仍然入库，Update 审计也仍然保留。只有 `/ask`、`/help` 和下面两条自助命令例外。

成员可以自己进出名单，不需要管理员：

| 命令 | 效果 |
| --- | --- |
| `/ignoreme` | 把发送者自己的 ID 加入当前会话的忽略名单，立即生效。 |
| `/unignoreme` | 把自己从名单移除，立即恢复接收；被忽略时也能用。 |
| `/ask 问题` | 所有成员都能显式唤起，包括被忽略的成员。 |

这几条命令只改发送者自己，作用于该 Chat 的全部 Topic，不影响其他会话；结果写回 `config.jsonc`，重启后仍然保留。匿名身份不能使用自助忽略命令。管理员也可以直接编辑 `ignored_user_ids`，这个字段是热更新的。

## 活跃时段与注意力窗口

默认情况下，允许范围内的群聊遇到可触发消息就会开一个消息批次。配置了活跃时段之后，时段外只有「直接叫到它」的消息能开批次；命中之后，这个会话进入一段注意力窗口，窗口内的后续消息按活跃时段内处理。

```jsonc
{
  "telegram": {
    "participation": {
      "active_windows": [
        { "start": "09:00", "end": "12:00" },
        { "start": "20:00", "end": "01:00", "days": [5, 6, 7] }
      ],
      "trigger_keywords": ["塑料碗", "wan"],
      "attention_window_seconds": 300
    }
  }
}
```

- 时段按会话时区解释；`days` 用 ISO 星期 1–7，不写表示每天。
- 结束时间早于开始时间表示跨午夜，`24:00` 表示当天结束。开始与结束相同的时段会被 `check-config` 拒绝。
- 关键词匹配消息正文和 caption，忽略大小写；带标题、列表、表格或图片的富文本消息匹配其中看得见的文字，链接地址和文件名不算。
- 全局与会话两层的 `active_windows` 是**整体替换**：会话写了就用自己的列表，写空数组表示这个会话没有时段。`trigger_keywords` 则是**追加**：会话的关键词加在全局列表之后，写 `[]` 表示不额外增加。
- 注意力窗口按 Chat + Topic 单独计时，长度由 `attention_window_seconds` 决定，默认 300 秒。

时段外能开或刷新窗口的只有四种消息：`/ask`、直接 @ Bot、回复 Bot 自己发过的消息、命中触发关键词。窗口在时段内不会被记录，所以时段结束就立即回到静默，不会多留一个窗口。

面板里点「编辑活跃时间」可以选四种模式：「不限制活跃时间」（移除本会话的时段设置）、「自定义活跃时段」（按时段与星期生效）、「无固定活跃时段」（普通消息不会唤起，只有 @、回复或关键词可以）、「仅 /ask 唤起」。对话框同时显示关键词与注意力窗口的保留情况。

## 仅 /ask 唤起

全局 `telegram.participation.ask_only` 或会话级的同一个字段设为 `true` 之后，只有 `/ask` 能唤起 Bot：普通消息、@、回复、关键词、Sticker 和其他 Bot 的消息都不会开批次。

- 默认关闭；会话值覆盖全局值，显式写 `false` 可以退出全局开启的模式。
- 这个模式下开出的批次是 0 秒收集窗口、不附带其他 Bot 的消息，也不留注意力窗口。
- 消息照常保存，下次被唤起时作为历史可见，群聊记忆也照常整理。活跃时段、关键词和注意力窗口此时都不生效，不必删掉原配置。
- 私聊不受限制：私聊里每条消息都直接针对 Bot。

```jsonc
{
  "telegram": {
    "chats": [
      {
        "id": -1009876543210,
        "participation": { "ask_only": true }
      }
    ]
  }
}
```

这个字段是热更新的，保存后立即生效。成员发送 `/ask 问题内容`，一条消息里写完问题即可；它只收这一条，不会顺带别的消息。暂停、睡眠等闸门仍然有效，模型仍自行决定要不要发言。

## 每个会话的主动回复

主动回复是加在普通群消息上的按会话概率闸门，默认关闭。会话层的三种选择：

- **沿用全局设置**：删除本会话的覆盖，逐项继承全局值。
- **关闭主动回复**：本会话只有直接叫到 Bot 的消息才会触发。
- **自定义本群参数**：单独设置第一次被选中的机会、每次未命中后增加多少、最多连续尝试次数（界面按百分比填写）。

只有普通群消息经过抽样；@、回复、关键词、`/ask` 和命令都不受影响。计数按会话隔离，Forum Topic 共享，存在数据库里。私聊不能配置主动回复，`check-config` 会直接拒绝。概率怎么算、怎么验证，见[按表现和费用调优](tuning.md)。

## 每个会话的入场闸门覆盖

入场闸门默认读取全局 `telegram.decision_gate`。若要给单个会话不同的判断口径，在「更多操作」→「编辑入场闸门」里逐个字段打开「为会话单独设置…」开关：

- 可以覆盖的六项：启用、模式、阈值、历史条数、批内条数、提问文本。
- 关闭开关表示继承全局值，保存时这个字段会从配置里删除；六项全部关掉再保存，整个覆盖对象会被移除。
- 连接字段（模型、地址、密钥、超时）只有全局一份，会话不能指向别的端点或凭据。
- **私聊不能配置入场闸门**，也没有这个入口：私聊是直接对话，不是一批群消息。

保存后热应用。全局段必须已经写了 `api_key`，否则把会话的「启用」打开会被 `check-config` 拒绝。字段含义与观察顺序见[按表现和费用调优](tuning.md)。

## MCP 绑定与工具收窄

默认情况下，每个会话都能用到全部已配置的外部 MCP 服务器，按服务器自己的设置来。需要收窄时，在「MCP 服务器」对话框里选：

- **继承全部服务器**：不写绑定，行为和没配置一样。
- **不使用 MCP 工具**：写入空绑定，这个会话一个 MCP 工具都调不到。
- **显式绑定**：挑选服务器，并可以为每个服务器选定允许的工具子集。

绑定只能收窄，不能扩大：选定的工具必须是服务器本来暴露的工具；如果服务器允许全部工具，工具列表要等它连接之后才知道，面板这时只能编辑已保存的选择。写死的工具必须能解析到策略（自己的覆盖、服务器上的条目，或服务器的默认策略），否则 `check-config` 报错。

绑定是热更新的：收窄会让受影响的会话停跑并自动续跑，新增服务器或放宽工具不会打断正在跑的运行。`mcp.servers[]` 的字段与 `exposure`、`skills` 等选项见[外部 MCP 配置](../configuration/mcp.md)。

## 快捷跳转

「更多操作」→「打开相关页面」会把当前会话作为 `?chat=<会话 ID>` 带到别的页面，列表直接筛到这个会话：提示词、辞典、记忆、群聊记忆、消息、运行记录、提醒。排查某个群的问题时，先从这里跳进运行记录最省事。

## 移除配置与删除数据是两件事

这两种做法都会让 Bot 停止处理这个会话，但数据完全不同：

- **从配置里移除**（手改 `config.jsonc` 或通过接口写文件）：热更新。会话从生效配置里消失后，它的运行会被停掉、新消息被拒绝，但历史消息、上下文、记忆条目、图片和审计**全部保留**。之后把它加回配置，一切照旧。
- **在面板删除**（「删除」→「删除会话」）：先移除配置，再停掉并等待这个会话正在进行的运行结束，然后删除它的记忆条目、图片和已存储的消息。删除不可撤销。

面板删除还有两种「没有删干净」的明确答复，都是保留数据的：

- `chat_delete_pending`：配置已经改好，但还有运行没停下来。稍后重新加载再删一次。
- `chat_still_authorized`：存储里的迁移记录把这个 ID 和另一个仍在配置中的会话 ID 连在一起，说明它可能仍然可达，数据因此保留。

## 确认改动生效

- **会话**页的「状态」列显示每个会话是「生效中」「有待生效更改」「待添加」还是「待删除」。
- 需要重启才能生效的改动（例如话题范围）保存后，页面顶部会出现「N 项设置正在等待重启」的横幅和「立即重启」按钮；不能从面板重启的部署会提示手动重启。哪里能改、哪里不能，见[配置生命周期](../configuration/lifecycle.md)。
- 依赖细节时看运行记录：`/status` 显示当前会话生效的模型，`/effort` 显示当前会话接受的思考档位与本群覆盖的级别；运行详情的「模型调用」里能看到那次运行实际用的 Provider、模型与思考强度。
