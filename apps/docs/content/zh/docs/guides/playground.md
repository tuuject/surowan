# 用虚拟群聊试验人设和工具

虚拟群聊（Playground）是面板内置的沙盒。房间里的输入走的是和真实群聊同一套调度、运行时与模型配置，但所有输出只回到房间，不会发往 Telegram。适合在不动真实群的情况下试人设、看回复、判断模型到底会不会接话。

房间不是 mock：放行会真的调用模型，也真的计费。想省钱就别放行。

## 1. 建房与身份

1. **虚拟群聊 → 新建房间**，填房间名称，可以顺手填写 **初始身份**（逗号分隔）。新房间默认暂存消息，图片生成默认关闭。
2. 房间有自己的身份列表，名称允许重复——用来模拟同名群友，每个身份彼此独立。身份分成员与管理员，只影响界面上的展示，不授予命令权限。
3. 在时间线下方选 **发送身份**，写消息，点 **发送**。可以对某条消息选择回复，模型看到的引用关系与真实群一致。

一条消息最多附 4 张图片，单张不超过 10 MiB，仅 JPEG / PNG / WebP。

## 2. 暂存与放行

房间没有「发了就自动运行」的模式：新消息默认进入暂存队列，不会启动任何模型调用。

- **放行 N 条**：把当前待处理的消息封成一个批次，排队一次真实运行，也只结算这一批。没有待处理消息时，放行只关闭暂存，不产生调用。
- **暂存新消息**：重新打开暂存，之后的输入继续排队。
- 放行之后输入按接纳顺序进入运行；同一房间同时最多一个运行，上一条还在跑时新的批次排队等待。
- 房间标题行会显示版本、暂存状态与待处理数量；标题行下方的 `queued` / `running` 是排队与运行中的数量。

## 3. 读时间线和运行结果

时间线上每条消息带状态徽标：**暂存中**、**已放行**、**成功**、**失败**、**已过期**。Bot 的输出以房间消息出现，回复哪条会标出序号。

**运行** 列表记录每次放行：`排队中`、`运行中`、`已完成`、`失败`、`已中止`、`结果未知`，以及 Token 用量、费用与 **审计** 链接——审计打开的是和 Telegram 群共用的 Invocation 详情页，能看工具调用、模型请求、房间发送与冻结上下文。

三种结果要分清：

- **有输出**：时间线上出现 Bot 的消息，运行一般显示 `已完成`。
- **主动沉默**：运行结束，但写着「本次运行结束但没有发布任何消息」。这是模型的选择，不是失败。
- **失败或中止**：展开运行看错误；`结果未知` 是进程中断导致的不确定状态，先核对时间线与审计，不要盲目重试。

## 4. 重试，以及它和真实运行的续跑

失败或中止的运行可以点 **重试这次运行**，但门槛很窄：

- 只有 `失败` 或 `已中止` 的运行可以重试；`结果未知`、已完成、排队中都拒绝。
- 那次尝试必须**零副作用**：没有发过消息、没有调用过工具、没有调用过模型、没有注入过上下文。
- 同一房间已有更晚的放行时拒绝，避免把顺序打乱。

不满足条件时页面会给出原因。真实群聊里失败的运行是另一套机制：在 Invocation 详情里 **Resume** 续跑，只对某个会话最新的一次失败运行（含已中止与结果未知）生效。两者不要混用——房间重试是「这次尝试根本没开始」，续跑是「这次真的跑过，但从断点接着跑」。

## 5. 图片生成的费用边界

每个房间有独立的 **图片生成** 开关，默认关闭。打开后，这个房间的模型可以真实调用生图服务，**会产生费用**；页面会记下是谁在什么时候打开的。

- 开关本身不校验全局图片配置：全局 `image` 段没配好时，打开也生不出图。
- 关闭只阻止新的提交，已经受理的生成会继续完成，成品回执仍会送回房间。
- 开不开与房间之外的费用无关；生图配置本身见[看图、Sticker 与图片生成](images.md)。

## 6. 作为循环闹钟的试运行目标

**循环闹钟** 的目标列表里包含所有 Playground 房间（显示为 `Room: 房间名`）。想验证一条周期性提示词的效果，又不希望它一上来就在真实群里说话，可以先把闹钟指向房间，观察几次触发，再改成真实会话。

闹钟的规则、Cron 与立即执行见[开启搜索、定时任务与外部工具](tools.md)；一个闹钟保存后目标不能改，要换目标只能新建一条。

## 7. 房间里不适用的东西

房间是一套收窄的执行配置，与 Telegram 那套无关：

- **没有入场闸门**：闸门设置来自 `telegram.*`，房间不受它影响，也不会产生闸门判断记录。
- **没有活跃时段、`仅 /ask 唤起` 与主动回复抽样**：这些都属于 Telegram 的参与设置。
- **没有贴纸、提醒、辞典写入和 MCP 工具**：房间的技能列表里没有它们。
- 房间有自己的 Memo 与图片素材，与 Telegram 会话完全隔离；删除房间会一并删除。
- 房间的模型用量记在独立的 `playground` 用量域，不会挤占 Telegram 会话的日预算；但用的是同一套上限配置。

房间的消息、运行与审计随 `retention.online_days` 清理，本地图片素材随备份保留。细节见[升级、备份与恢复](maintenance.md)、[数据路径与保留](../configuration/storage.md)与 [`retention` 字段参考](../configuration/fields-retention.md)。

## 8. 常见误区

- **房间不是 mock**：放行就是真实模型调用，和真实群一样计费。
- **暂存不是暂停**：它只让新输入停在待处理队列，不取消已排队的运行，也不停止已经开始的生图。
- **「结果未知」不是失败**：进程在发送途中中断时，那次运行可能已经产生了真实副作用，先核对再决定。
- **房间不是群**：这里的身份不会出现在任何真实聊天里，房间里的 @、Topic、Sticker 也不会发生。
