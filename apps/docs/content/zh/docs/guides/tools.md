# 开启搜索、定时任务与外部工具

这一页讲三类「让 Bot 能做得更多」的能力：

- **网络搜索与网页读取**：让模型先找到来源，再读正文或图片。
- **定时任务**：Bot 自己的一次性提醒（Alarm）与管理员设定的循环闹钟。
- **出站 MCP**：让 Bot 调用外部 MCP Server 的工具。

三者都只通过既有的工具边界发生，能力开关、只读策略、超时、大小限制与审计照常生效，任何配置都不会给模型新的授权。

## 网络搜索

网络搜索让模型在不知道具体 URL 时先搜索，拿到标题、URL 与简短摘要，再按需用 `web_fetch` 读正文。搜索本身不抓取正文，所以一次搜索只占很小的上下文。

默认**不启用**。启用后 `web_search` 能力与对应的 Skill 才会出现在模型的索引里。

### 在面板配置

打开 **网络搜索（Web search）**：

![网络搜索页：已配置的引擎与 URL 过滤](__DOCS_BASE__/screenshots/tools/search-settings.zh-CN.light.png)

- **启用网络搜索** 控制整个功能。关闭它，或禁用全部引擎，效果相同：能力与 Skill 立即消失，**正在进行的运行会停止**，下一条消息用重建的上下文。
- **搜索引擎** 可以添加多个。每个引擎填：服务商、模型可见的**引擎 ID**（小写字母、数字、短横线）、**服务地址**（留空用服务商默认；SearXNG 必填）、**结果条数**（1–10）、**超时（秒）**（5–30）、以及一条**给模型看的备注**。备注会出现在工具描述与引擎列表里，说明这个引擎适合搜哪些网站或内容，模型据此挑选引擎。
- **密钥** 决定凭据来源：保留已配置的密钥、输入新密钥，或选用 Keychain 里已有的条目。新密钥按引擎 ID 命名写入同目录 `key.json`，面板与配置回读都只显示「是否已配置」。删除引擎**不会**自动清理它的密钥条目，未使用的条目在**密钥（Keychain）** 页清理。
- **URL 过滤** 用来丢弃不需要的结果。每行一个正则表达式（**RE2 语法**，不支持 `(?=…)` 这类前后行断言和反向引用），例如 `csdn` 会丢弃所有 `blog.csdn.net` 结果。下方的 **测试 URL** 可以粘贴 URL 预览命中情况，不会发起任何真实搜索。

服务商由内置插件提供：`tavily`、`brave`、`exa`、`firecrawl`、`deepseek`、`searxng`、`youcom`。用未注册的服务商会被拒绝。除 SearXNG 外都有默认地址，可用 `endpoint` 覆盖（例如接入兼容协议的中转服务）。

保存立即生效，无需重启。修改服务商、密钥或搜索参数**不会**打断正在进行的运行：每个请求在开始时冻结自己的引擎、地址、密钥、条数与超时，在途请求用旧配置完成，下一次搜索用新配置。只有「整体从可用变为不可用」才会停跑。

### 模型怎么用

- 模型看到的是几个引擎及其备注，可以按需指定 `engine`，也可以不指定。
- 面对有时效性的问题，Skill 要求模型在查询里带上当前年份或你提到的时段，否则引擎容易把旧页面排在前面。
- 搜索失败**不会**自动重试。认证失败、额度耗尽、限流、上游不可用、请求被拒、重定向、超时、响应过大与网络错误会分别报告。
- 结果被 URL 规则过滤时，结果头部会说明丢了多少条。
- 返回内容始终是不可信数据，不能当作指令或授权。

字段与校验见[网络搜索配置](../configuration/web-search.md)与 [`web_search` 字段参考](../configuration/fields-web-search.md)。

## 网页读取与看图

`web_fetch` 是「按 URL 取一页」的能力，不是搜索，也不是通用 HTTP 客户端：

- 只做无 Cookie、无认证 Header 的 HTTP(S) GET，不执行 JavaScript，不支持登录。内网、环回、非标准端口与不安全的重定向默认拒绝。
- HTML 页面默认抽取正文并转成 Markdown（站点支持内容协商时优先要 Markdown，可用 `web_fetch.accept_markdown: false` 关闭），需要原始 HTML 时才显式请求。
- 正文里的图片保留为带完整地址的 Markdown 图片链接。画面内容确实重要时，模型可以再用 `web_fetch` 打开那张图片的链接：**JPEG、PNG、WebP 会作为图片交给模型查看，单张最大 20 MiB**，GIF、AVIF 等格式不支持。
- 遇到防盗链时可以带上 `referer`（通常填所在网页的地址）。只有支持图片输入的模型才看得到画面，否则只会收到一段说明。
- 需要 JS 渲染、登录或复杂解析时，请接入 MCP。

`web_fetch.dangerously_allow_all_ip_addresses: true` 会取消全部地址限制，让任何能触发 Bot 的人借模型访问你的内网，只在完全信任这些人时开启。完整字段见[网页读取配置](../configuration/web-fetch.md)与 [`web_fetch` 字段参考](../configuration/fields-web-fetch.md)。

## 定时任务：一次性提醒与循环闹钟

这是两种完全不同的东西：

| | 一次性提醒（Alarm） | 循环闹钟（Recurring alarms） |
| --- | --- | --- |
| 谁创建 | 群里的人让 Bot 记下 | 管理员在面板创建 |
| 周期 | 一次性，到点触发一次 | 按规则或 Cron 反复触发 |
| 提示词 | 用户的原话 | 管理员写的可信提示词 |
| Bot 能改吗 | 能（`alarm` / `list_alarm` / `delete_alarm`） | 不能，也看不到面板标题 |
| 面板位置 | **提醒（Alarms）**，只读审计 | **循环闹钟（Recurring alarms）** |

一次性提醒创建的是持久任务。到期后生成完成回执，若同一会话已有可接收注入的运行，回执会在当前工具链结束后注入，否则等可以启动时开新运行。模型决定要不要用 `send` 跟进，而不是预先保存一段话。它不是通用后台 worker。每个运行最多创建 3 个提醒。

## 循环闹钟

循环闹钟让 Bot 按时间表主动做事，例如每天早上八点在群里问候，或每天下午六点整理一份简报。每个循环闹钟由四部分组成：发到哪个会话、什么时候触发、用什么时区、触发时交给 Bot 的提示词。

只能由管理员在 **循环闹钟（Recurring alarms）** 页创建和修改。群友不能申请，Bot 自己也不能创建、查看或删除循环闹钟。

### 创建

![循环闹钟编辑对话框：规则、Cron 与未来 5 次预览](__DOCS_BASE__/screenshots/tools/recurring-alarm.zh-CN.light.png)

1. 点「新建循环闹钟」。
2. 填**标题**：只在面板里显示，Bot 看不到它。
3. 选**目标**：已配置、Bot 已经见过的会话（配置了 Topic 白名单的群按 Topic 列出），以及 Playground 房间（用房间试效果不会打扰真实群聊）。暂时无法接收消息的目标会标出原因，不能选。**保存后不能更换目标**，换目标请新建一个。
4. 填**时区**（IANA 名称，例如 `Asia/Shanghai`），新建时默认使用全局时区。每个循环闹钟记住自己的时区，以后修改全局时区不会让已有的「早上八点」跟着移动。
5. 写**提示词**，最长 4000 字符。它是你下达的可信指令，Bot 会像你在群里提出要求一样去执行，但仍然只能用它本来就有的工具，提示词不会给它新的权限。
6. 决定是否**启用**，然后创建。

每个会话最多 20 个循环闹钟。配置了 Topic 白名单的群按 Topic 计数，Playground 房间各自计数。

### 执行周期

执行周期有两种视图，编辑的是同一份规则：

- **规则**：分、时、日、月、星期五个字段，每个字段选「每」或「第」。「每」留空表示每一个单位都触发，填 N 表示每隔 N 个单位，「第」后面填具体值，多个值用逗号分隔，例如分钟填 `0,30` 表示整点和半点。星期直接勾选。
- **Cron**：每行一条标准 5 段表达式：`分 时 日 月 星期`。例如 `0 8 * * *` 是每天 8:00，`30 9 * * 1-5` 是工作日 9:30，星期 `0` 是周日。

要点：

- 可以添加多条规则，任意一条命中就触发。
- 同一条规则里同时限定了「日」和「星期」时，两者满足其一即可，和常见 cron 一致。
- 不支持秒段与年段，也不支持 `L`、`W`、`#`、`?` 这类扩展写法。
- 用 Cron 写了规则控件表示不了的写法（例如范围 `1-5`）后，只能继续用 Cron 编辑。
- 编辑时下方会预览接下来的 5 次触发时间，按所选时区显示。两次触发间隔小于 5 分钟时会提醒，但仍然可以保存。

### 到点时会发生什么

- 目标会话里 Bot 正在运行时，这次任务会在当前工具链结束后并入，否则新开一次运行。
- 它**不占每日 Token 预算**，Bot 处于睡眠时段时也照常执行。Playground 房间同样如此。
- 提示词以 `<admin_scheduled_task>` 可信块交给模型，带上计划时间与合并掉的错过次数。
- 和平常一样，只有模型真的调用发送工具时消息才会出现在群里。

以下情况这一次会被跳过，并在触发记录里写明原因，闹钟本身保留：

- 服务停机或平台断线，恢复时已经比计划时间晚了 30 分钟以上。晚得不多时，期间错过的多次只补发一次（并记录合并了多少次）。
- 目标会话已暂停、已从配置里移除，Topic 不在白名单里，或主模型没有配置完整。
- 上一次触发还没投递完。

### 立即执行、编辑与删除

- 每一行的 **立即执行（Run now）** 用已保存的提示词马上执行一次，适合调提示词时看效果。它和到点触发走同一条路径，Bot 看到的内容完全一样，不改变执行周期，停用状态下也能用，但上一次还没投递完时不能用。
- 编辑时修改执行周期或时区，下次触发时间会从当前时间重新计算，只改提示词会影响之后的触发。开关可以停用或启用，停用后保留执行周期但不再触发，还没开始投递的那一次会被取消。
- 删除会移除执行周期和触发记录，同样取消还没投递的那一次。
- 点**详情（Details）** 查看最近 50 次触发：计划时间、来源（定时或手动）、结果、操作者，以及处理它的那次运行。

### 用 API key 管理

API key 也能管理循环闹钟（`surowan-utils` 的 `recurring-alarm` 命令或 MCP 工具）。查看与预览只需要读权限。新建、编辑和立即执行会让 Bot 在无人值守时调用模型，需要同时具备写权限和付费操作权限。删除只需要写权限。

## 出站 MCP

出站 MCP 让 Bot 调用外部 MCP Server 的工具。Server 由管理员显式配置，可用 stdio（运行宿主机上的命令）或 Streamable HTTP，模型只在这里被允许的 Server 与 Tool 范围内活动。

### 在面板管理

打开 **MCP 服务器（MCP servers）**：

![MCP 服务器页：状态、渐进式暴露与技能列表](__DOCS_BASE__/screenshots/tools/mcp-servers.zh-CN.light.png)

页面显示每个 Server 的实时状态（**就绪** / **连接中** / **不可用** / **无实时状态**，含错误码）、连接摘要、它发现过的全部工具（含被工具选择隐藏的），以及使用情况（哪些会话显式绑定、哪些会话靠继承使用）。

- **添加服务器**只接受 Streamable HTTP Server：别名、URL、Header 密钥、工具选择、上限与策略。stdio Server 运行的是宿主机上的命令，必须在服务器的 `config.jsonc` 里手工添加。
- **编辑**时 HTTP Server 可以改 URL 与 Header，stdio Server 只能改工具选择、上限与策略，命令、参数、环境变量与传输方式保持只读，页面会明确提示这些字段只在 `config.jsonc` 里维护。两种 Server 都可以改暴露方式、描述与技能开关。
- **删除**要求先解绑：还有会话显式绑定该 Server 时会返回绑定它的会话列表。不写 `mcp` 字段的会话继承全部 Server，删除后它们自动失去这个来源。
- 工具名形如 `别名__工具`，所以别名必须以字母开头，只能使用字母、数字、下划线或短横线。

### 直接暴露与渐进式暴露

每个 Server 可以单独选择**暴露方式**：

- **直接暴露（Direct，默认）**：每个工具都以 `别名__工具` 作为独立工具交给模型，每次请求都带上完整定义。
- **渐进式暴露（Progressive）**：这个 Server 的工具不进入工具列表。模型只看到一个 `mcp` 工具，它的说明里列出所有渐进式 Server 的别名、工具数量与描述，模型需要时用 `mcp` 的 `search` 找工具（中英文都可以搜）、`help` 读完整说明与参数，再用 `call` 调用。

工具多的 Server 适合渐进式，所有渐进式 Server 加起来只占工具列表里的一个位置，不会让每次请求都背着几十份工具定义。代价是模型多一次查找，而且它一开始只能靠**描述**判断这个 Server 能不能帮上忙，所以描述要写好（最长 1000 字）。没写描述时模型只能看到几个工具名，**警告（Warnings）** 页会显示 `mcp_description_missing` 提醒。

描述可以手写，也可以让工具模型根据 Server 公布的工具起草：点「用工具模型起草」。起草是一次**计费**的工具模型调用，结果只是草稿，只会填进输入框，确认并保存后才会写入。

渐进式不放宽任何权限，`mcp` 只能找到并调用这个会话本来就能用的工具（按会话绑定照常收窄），调用走与直接暴露相同的参数校验、只读策略、超时、大小限制与审计。审计里会有两条记录：外层的 `mcp`，以及真正被调用的 `别名__工具`。

### Server 发布的 Skill

支持「MCP with Skills」扩展的 Server 可以同时发布 Skill（说明如何使用它的工具的文档）。每次连接后会发现这些 Skill，并逐个校验文件内容、大小与摘要，校验不通过的直接丢弃，不影响该 Server 的工具。

模型用 `read` 读取这些文档（`mcp-skill://`），范围只限这个会话本来就能用到的 Server。**它们来自外部 Server**，只能说明如何使用该 Server 的工具，不能覆盖 Tool 约束或授权规则。

每个 Server 有一个**向模型提供技能**开关，省略即开启。关掉后模型读不到它的 Skill，修改它不会重连 Server，下一次运行生效。

### 后台建连、降级与恢复

启动**不会**因为某个 Server 连不上而等待或失败。每个 Server 都在后台连接，连不上或校验不通过的实例显示为**不可用**并按退避自动重试，不影响其他 Server、启动与本次热应用。

只有**就绪**的 Server 会把工具交给模型。不可达期间它的工具从下一次运行的注册表中消失，恢复后自动回来。不可用期间**警告（Warnings）** 页显示 `mcp_server_unavailable` 警告（连接中不告警）。

### 热应用与按会话绑定

`mcp.servers` 与每个会话的 `mcp` 都可以热应用，不需要重启。在 **设置（Settings）** 点应用配置或任何一次面板保存之后，新增的 Server 会被连接、删除的会被关闭、改过字段的会被替换，没改的保持连接。

改变某个会话能用的工具（删掉绑定、换工具列表、改策略，或它用的 Server 被改）时，这个会话正在进行的运行会被**停下、上下文被重建、然后自动续跑一次**。模型看到的是新的聊天记录，会被告知这次是运营者改了 MCP 配置，并收到被停下时结果未知的 MCP 工具名，避免重复副作用。只是新增 Server 或加宽工具列表不会打断正在跑的对话。只改暴露方式或描述也不会重连 Server、不打断任何对话，下一次运行起按新方式交给模型。

按会话绑定在 **会话（Chats）** 页每行的 **MCP servers** 入口设置：

- **继承全部**（不写 `mcp` 字段）：拿到全部 Server 与它们自己的设置。
- **完全关闭**（空数组）：这个会话没有任何 MCP 工具。
- **显式绑定**：挑选 Server 并收窄工具，可以给某个工具在这个会话里单独指定只读策略与超时。

绑定只收窄，不改连接，命令、URL、环境变量与 Header 仍属于 Server。需要两种连接就配两个别名。Playground 房间永远没有 MCP 工具。

配置字段见[外部 MCP 配置](../configuration/mcp.md)与 [`mcp` 字段参考](../configuration/fields-mcp.md)，按会话的字段见 [Telegram 配置](../configuration/telegram.md)与 [`telegram` 字段参考](../configuration/fields-telegram.md)。

## 只读文档与外部工具的区别

「扩展」在这个项目里有严格的边界，不要混淆：

- **System Skills** 是随版本发布的**只读** Markdown 文档包。System prompt 里只有索引，模型要用 `read` 读取 `system:///skills/<name>/SKILL.md`，再按文档用 `execute` 调用内部能力。Skill 是说明书，不是权限文件，不能绕过工具 Schema、引用校验、allowlist、预算或发送边界。
- **内置插件**（网页读取、网络搜索与其七家服务商、图片生成、Alarm、辞典）随发行版编译发布，用户侧只能通过配置启用或调整。插件之间可以声明依赖与扩展点，但没有插件市场。
- **出站 MCP** 是唯一由管理员接入的外部工具来源，且必须显式配置、经过 allowlist、只读策略、超时与大小限制。
- 当前**没有** Skill 上传、插件热装或第三方市场入口。

## 常见误区

- 网络搜索不是「把网页抓下来」，它只给标题、URL 与摘要，正文要用 `web_fetch` 读。
- `web_fetch` 不是任意 HTTP 客户端，也不执行 JavaScript，需要登录或渲染时请接 MCP。
- 循环闹钟不是 Bot 的一次性 Alarm，也不能让群友创建，提示词可信不等于工具权限更大。
- 渐进式暴露不改变权限，只是换了一种发现方式。
- 「模型看到了工具名」不等于「调用成功」，去**运行记录（Tool sessions）** 里看具体调用与结果。
