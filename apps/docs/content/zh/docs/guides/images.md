# 看图、Sticker 与图片生成

图片相关的行为分成三条互不相同的链路，先分清它们，后面的设置才不会配错地方：

| 链路 | 用到的模型 | 在哪里配置 |
| --- | --- | --- |
| 直接看图：新消息里的图片附带给主模型 | **Agent** 模型（必须支持图片输入） | [Agent 配置](../configuration/agent.md) 的 `providers` 模型能力 |
| 按需看图：更早的图片、Sticker 由 `read_image` 分析成文字描述 | **Vision** 模型（可与主模型不同） | [Vision 配置](../configuration/vision.md) |
| 画图与改图 | 生图上游服务（内置 OpenRouter adapter） | **图片设置（Image settings）** 或 `image` 段 |

## 直接看图与 Vision 的分工

这两件事经常被混为一谈：

- **主模型支持图片输入**时，最新一个批次里收到的照片与受支持的图片文件会直接附带给主模型，顺序与消息里的 `figure_N` 一致。附件不会被保留。
- **更早的图片**（包括前面批次的 `figure_N`）和所有 Sticker，都要模型主动调用 `read_image`，由 **Vision** 模型分析并返回文字描述。
- 没有配置 Vision 时，`read_image` 不可用，`figure_N` 之外的历史图片和 Sticker 都看不到；Sticker 的视觉索引也会暂停（已导入的贴纸保持待处理，不累积失败）。
- Vision 有独立的模型、思考强度、并发与每日预算（`max_tokens` 与 `max_images`），见[Vision 配置](../configuration/vision.md)与 [`vision` 字段参考](../configuration/fields-vision.md)。

图片不是随便能引用的：只有当前 Conversation 授权且未过期的 `img_` / `stk_` 引用可读，引用按 Conversation 隔离，过期即失效。系统不接受任意 file ID 或 Chat ID。

## Sticker 与贴纸集

Bot 只会发送你允许的贴纸集里的贴纸。它们写进 `telegram.sticker_sets`，在 **贴纸集（Bot sticker sets）** 页管理，改动立即生效，无需重启。

![贴纸集页：已配置的贴纸集与贴纸搜索索引](__DOCS_BASE__/screenshots/images/sticker-sets.zh-CN.light.png)

### 添加、编辑与删除

1. 点「添加贴纸集」，填 **Telegram 贴纸集**：贴纸集名称（字母、数字、下划线），或直接粘贴 `https://t.me/addstickers/…` 分享链接。
2. 填**昵称**：以字母开头，可用字母、数字、`_` 与 `-`，最长 64 字符。
3. 可选填**备注**（最长 500 字符）：写给模型看的使用说明，例如「调侃朋友时使用；严肃话题中避免」。模型挑贴纸时会看到每个贴纸集的昵称与备注。
4. 保存后 Bot 会在后台从 Telegram 下载这些贴纸并逐张建立视觉索引，页面显示同步与索引进度。**索引需要已配置 Vision 模型**。

几条容易踩到的规则：

- **指向的 Telegram 贴纸集添加后不可更改**：要换成别的贴纸集，删除后重新添加。
- 编辑只能改昵称与备注。改名或改备注不会中止正在进行的回复，新内容在下一批消息时生效。
- 添加或删除贴纸集会中止正在进行的回复，让下一次回复直接看到新的贴纸列表。
- 删除只是让 Bot 不再使用它们；**索引会保留**，之后重新添加同一贴纸集时无需重新分析。

### 索引状态

页面下方是「贴纸搜索索引」，可以按贴纸集、索引状态（待处理 / 失败 / 已索引）筛选，并搜索描述或 emoji。每个贴纸一行，显示描述、使用的模型、失败次数、下次重试与更新时间和分析版本。失败会按退避重试（最长 6 小时），所以「失败 1 次」通常是临时的。

### 模型怎么选贴纸

模型看到的是一个 `<sticker_catalog>`，每个贴纸集一行（别名、备注、`贴纸 ID: emoji` 条目）。emoji 只是粗略提示；要真正使用某张贴纸，模型必须先调用 `search_stickers`（可以按 ID 检查候选，也可以按语义搜索），拿到 `stk_` 引用，再用 `send` 的 `kind: sticker` 发送。贴纸引用在一段时间后失效。

## 图片生成

### 启用与设置

`config.jsonc` 里没有 `image` 段时图片生成处于禁用状态：Bot 照常运行，只是模型看不到生图工具，面板也不显示图片相关页面。推荐在面板 **图片设置（Image settings）** 里启用：

![图片设置页：已启用、已添加模型、可以保存](__DOCS_BASE__/screenshots/images/image-settings.zh-CN.light.png)

1. 勾选**启用图片生成**。
2. **密钥来源**：可以选用已保存的 OpenRouter 凭据（比如 Provider 页里已经存好的那个），也可以输入新的 API 密钥。已有凭据留空即沿用。
3. 在 **OpenRouter 图片模型**下拉框里搜索并选择模型，选择**供应商**，点「添加所选模型」。模型名称、内部 ID、路由标签、参考图上限、输出上限、比例与质量档位会自动填好。
4. 每个模型卡片都有**用途与提示词备注**（最长 1000 字符），写下这个模型适合的画风与提示词偏好。它只供聊天里的 Agent 选型与写提示词参考，**系统不会把它发给上游**。留空表示没有额外偏好，不要在这里填密钥。
5. 点「保存并应用」立即生效，无需重启。

能力取「所选供应商的元数据」与「本项目支持范围」的交集。要求必填参考图、或只输出 SVG 的模型暂不可添加，页面会说明原因。目录加载失败不会清空已配置的模型。

几条行为约定：

- API key 明文只写入配置同目录的 **Keychain**（`key.json`），`config.jsonc` 只保留凭据引用。
- 关闭开关会删除整个 `image` 段，但 Keychain 条目保留，等你在**密钥（Keychain）** 页显式清理。
- `image` 段的所有变化都是热更新，包括启用与禁用本身。
- 保存时如果配置文件已在别处被修改，会提示冲突，刷新后重试。
- 设置页显示已启用但工作台仍显示禁用时，检查日志里的 `image_service_warning`（例如凭据无法读取）；修好后在 **设置（Settings）** 应用配置。

也可以直接写配置，字段说明见[图片生成配置](../configuration/image.md)与 [`image` 字段参考](../configuration/fields-image.md)：

```jsonc
{
  "image": {
    "credentials": { "openrouter": { "env": "OPENROUTER_API_KEY" } },
    "models": [
      {
        "id": "gpt-image-1",
        "name": "GPT Image",
        "provider": "openrouter",
        "upstreamModel": "openai/gpt-image-1",
        "credentialRef": "openrouter",
        "providerTag": "openrouter",
        "capabilities": {
          "imageInput": true,
          "maxInputImages": 4,
          "maxOutputs": 4,
          "aspectRatios": ["auto", "1:1", "4:3"],
          "resolutionClasses": ["auto", "low", "medium", "high"]
        }
      }
    ]
  }
}
```

### 在聊天里画图

启用后直接在对话里提出请求即可，例如「帮我画一张霓虹雨夜的街景」或「把刚才那张照片改成水彩风格」。模型的实际流程是：

1. 用 `list_image_models` 只读查看当前模型目录（能力与备注），必要时用 `search_image_assets` 找共享素材。这两步不产生生成费用。
2. 调用 `image_generate` 提交意图：提示词、模型、比例、质量、张数，以及可选参考图。返回一个生成编号。
3. 生成在后台进行（通常几秒到几十秒），完成后一条任务回执注入对话。
4. 模型用 `send` 的 `kind: image` 把这次生成尚未交付的成品发出：单图直接发送，多图作为相册，可以附一句说明。

几个边界：

- **参考图只能来自两个渠道**：本会话里可见的 `img_` 引用，或素材库里「Agent 可以使用」的素材。后者只凭文本（名称、描述、分类、关键词）判断是否适用，模型看不到图片本身。跨会话、过期或伪造的引用都会被拒绝；每次提交都会复查素材仍可见且未归档。
- **每个运行最多提交 3 次生成**。同一个工具调用的重放（比如续跑）返回已有生成，不重复计费；重新点一次「生成」或让模型再提交一次是新生成，会重新计费。
- **已发图片默认不重复交付**：同一生成的同一成品不会因为重复调用或晚到的完成回执再次发出。
- **要原图时以文件发送**，见下一节。
- 生成失败时模型会用自己的话解释，不会反复重试；也没有绕过 `send` 的隐藏发图通道。
- 禁用图片生成后，模型与面板立即失去图片能力；再开启立即恢复。

### 要原图或要文件

图片按照片发送时会被 Telegram 压缩。只有当用户明确说要「原图」或「以文件发送」时，模型才会改用 `send` 的 `kind: file`：

- Bot 生成的图片：发送生图服务产出的原始文件。直接回复那张图说「发原图」，发出的是那次交付的全部原图。
- 会话里的其他图片：发送 Telegram 保存的那份。普通照片上传时已被 Telegram 压缩，发成文件也找不回更高画质；以文件形式收到的图片则原样转发。
- 贴纸不支持，会说明原因。
- 原图文件已清理时，会说明拿不到，不会拿压缩版冒充。
- 以文件发送不算图片交付，不影响重复交付判断。
- Playground 房间没有文件消息，不支持这种发送。

### 面板三页

**图片生成（Image generation）** 是工作台：

![图片生成工作台：提示词里内联了一张素材](__DOCS_BASE__/screenshots/images/generate-workbench.zh-CN.light.png)

1. 写提示词，或把素材插到光标处。参考图有三个来源：最近一排素材、**更多** 里搜索整个素材库、或在本页新上传。
2. 点选素材会插入 `{{image:<素材 ID>}}`；紧挨文本框的「引用中的参考图」一排随文本实时增删，点移除即删掉该素材的全部引用。
3. 提示词素材（`{{prompt:…}}`）仍原位展开；`{{image:…}}` 在提交时原位替换成「图 1」「图 2」这样的序号，图片交给绘图模型的先后就由这个序号决定。
4. 「解析预览」查看最终提示词，不计费。
5. 选模型、比例、质量与数量后点「生成」，输出显示在下方「本次输出」。每次点「生成」都是一次新的生成与计费。

**生图记录（Image generations）** 是审计列表：

![一条已完成的生图记录详情](__DOCS_BASE__/screenshots/images/generation-record.zh-CN.light.png)

点生成编号进入独立详情（也可直接打开 `/image-generations/<生成编号>`），包含状态、使用的模型、提交来源（管理员或哪个会话）、每次尝试的上游请求与用量、最终提示词、输出大图与错误信息。参考图按当时提交给模型的顺序展示并保留当时的名称，点击可看原图；素材归档后仍可查看，原图已清理时显示提示。失败的生成可以点「重试」。

**生图素材（Image assets）** 是提示词素材与参考图库：

![生图素材页：Agent 可用开关与 AI 提取](__DOCS_BASE__/screenshots/images/image-assets.zh-CN.light.png)

- 生成产物会自动进入图库；参考图可上传（单个不超过 20 MiB）、编辑与归档。
- 编辑弹窗可以改名称、描述、分类与关键词（整行最长 500 字符，逗号分隔），并切换**Agent 可以使用这个素材**。
- 该开关**默认关闭**。打开后，素材进入所有会话的素材搜索，聊天里的 Agent 就能查到并用作参考图；这是让素材跨会话可用的唯一方式。
- **AI 提取**让工具模型看图，提议名称与关键词：结果只填充表单，点「保存」才落盘。这是一次**计费的**模型调用。工具模型不能读图时会说明原因、给出工具模型配置页的链接，并允许为这一次提取临时选一个能看图的模型（临时选择不保存）。
- 保存只提交改过的字段，所以别的管理员在弹窗打开期间做的改动不会被一次保存悄悄覆盖。
- 归档的素材不再出现在选择列表与 Agent 的搜索结果里，已引用它的历史生成不受影响。

## 保留、备份与费用边界

- 生成记录与素材行随 `retention.online_days` 清理，原图文件随数据目录清理。
- `backup` 在生成 SQLite 快照的同时，会把 `<data_dir>/images` 一并拷贝为备份文件旁的 `.images/` 目录，恢复时两个一起放回，见[升级、备份与恢复](maintenance.md)。
- 费用边界分三处：每次生图由上游服务按其价格计费（本地没有额外配额，只有「每个运行最多 3 次提交」这一道闸）；**AI 提取**与辞典融合走 Tool Model 计费；**Vision** 分析有自己独立的每日预算（`vision.daily_budget`）。
