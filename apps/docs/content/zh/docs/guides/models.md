# 接入和更换模型

面板把模型相关的事情拆成两页：**供应商** 管连接和模型清单，**模型** 管「谁做哪项工作」。先有供应商，才有可分配的模型。

## 1. 两个页面各管什么

| 页面 | 你在这里做什么 | 改动如何生效 |
| --- | --- | --- |
| **供应商** | 新建连接、填密钥与地址、拉取或手动添加模型、编辑模型参数、做健康检查 | 保存即热应用；正在进行的回复仍按旧设置完成 |
| **模型** | 给主模型、图片识别、工具模型三项工作各选一个模型与思考强度 | 底部 **保存** 后统一写入并热应用 |

供应商页的模型行上有 **用作** 按钮组（主模型 / 图片识别 / 工具），点一下就能把这项工作交给它；已经担任的角色会高亮。这是快捷方式，思考强度仍在模型页调。

## 2. 添加供应商与模型

1. **供应商 → 新建供应商**，三步向导：
   - **接入方式**：选 **内置供应商**（地址与接口格式已预设，只需选一个供应商）或 **自定义接口**（自己填地址，适合中转服务或自建服务）。
   - **API 密钥**：粘贴密钥。只有供应商明确要求时才需要 **自定义请求头**。
   - **选择模型**：点 **获取模型列表**，勾选要启用的模型。列表拿不到的模型用 **手动添加** 按 ID 查询。
2. 只有被勾选（或手动确认）的模型才会写入配置，供应商目录里存在的其他模型对运行时不存在。
3. 创建后立即生效。想调整连接，选中供应商后可改地址、接口格式、密钥与请求头；**改了接口地址就必须在这次保存里重新填写 API 密钥和每个请求头的值**，这是为了避免把旧密钥发给新地址。
4. 换供应商或删模型时，如果还有模型担任着某项工作，面板会先拦下来，让你改派或取消勾选。

**接口格式** 决定请求长什么样：OpenAI (Chat Completions)、OpenAI (Responses)、Anthropic、Google。不确定时选 OpenAI (Chat Completions)，大多数服务都支持；OpenAI (Responses) 只有少数供应商支持。

## 3. 模型参数从哪来

手动添加或拉取时，面板会按模型 ID 查参数：先是供应商自己的列表（OpenRouter、Vercel、Gemini），然后是 [models.dev](https://models.dev)。

- **精确匹配**：上下文长度、最长输出、输入类型与思考档位直接填入，不用逐项确认。
- **价格**：能匹配到这家供应商自己的价格就用它；匹配不到时，取 models.dev 里各部署的最高价格（输入、输出、缓存读写各取最高）；完全没有价格就写 0。价格从不要求确认，保存后可以改。
- **查不到是否支持思考**：按「不支持思考」添加，界面上会标出来。
- **只有上下文长度、最长输出或输入类型查不到**（或者只匹配到名字相近的模型）时，这个模型才标 **N 项待确认**，必须打开编辑弹窗填好或确认 **待确认** 的项才能添加。

**昵称**（1–64 个字符）只影响 Telegram 命令里的显示：设置后 `/status`、`/model`、`/effort` 只显示昵称，不再暴露供应商与真实模型 ID；没有昵称时显示 `供应商 / 模型`。面板本身始终显示真实 ID。

镜像与内网部署可以换一个目录源：**开发者** 页底部的 **模型参数来源** 写入 `models_dev.api_url`，留空就是默认的 `https://models.dev/api.json`。它接受不带凭据与 `#` 片段的 HTTP(S) 地址，镜像必须返回同样的 JSON；保存后下一次查询就使用它，不需要重启。字段语义见[模型元数据目录](../configuration/models-dev.md)。

## 4. 分配三项工作

**模型** 页有三张卡片，职责不同：

| 卡片 | 它做什么 | 不设置会怎样 |
| --- | --- | --- |
| **主模型** | 读群聊和私聊，决定怎么回复 | 不会开始任何运行，Bot 不回复 |
| **图片识别模型** | 描述图片和贴纸，`read_image` 与贴纸索引都靠它 | 这两项不可用 |
| **工具模型** | 辞典融合、群聊记忆整理等后台任务 | 跟随主模型 |

- 主模型只要求能读文字（`text` 输入）。它能直接接收新消息里的图片是另一项能力，与图片识别模型是两件事：主模型支持图片输入时可以直接看图；图片识别模型是给它「细看某张图」和给贴纸建索引的那一个。
- 图片识别是可选角色。不配它，Bot 依然能聊天，只是不能主动细看图片、也不能给贴纸建索引。
- 思考强度只列出该模型真正接受的级别；不支持思考的模型不能调。切换模型时，原来的级别如果新模型不接受，会被重置为它最弱的一档（通常是 `off`）。
- 改动不会立刻写入：有改动的卡片标题旁会出现小圆点，底部保存栏显示未保存的数量。点 **保存** 一并写入并热应用；点 **放弃更改** 恢复成已保存的值。

**切换主模型会发生什么**：如果还有运行正在用旧模型，面板会弹出 **终止进行中的运行并切换？**，并列出数量。确认（**终止并切换**）后，这些运行立即终止，它们正在处理的那批消息不会得到回复；之前委派的任务不受影响，之后的消息交给新模型。取消则什么都不保存。

只有手改配置文件再应用时例外：那种情况下正在运行的 Invocation 会用旧模型跑完。Telegram 里的 `/model` 也只切换本群模型，不弹窗，回执会说明终止了几个会话。

## 5. 健康检查

在 **供应商** 页选中供应商，点模型行的 **测试**；要批量测试，勾选模型行左上角的复选框（可跨供应商累计），再点 **测试**。一次最多同时发出 3 个请求，每项独立显示结果。

- 这是真实模型调用，可能计费，但不切换当前角色、不附带人格 Prompt 或聊天历史。
- 唯一提示词固定为 `reply with extract content: ok`，每次最多等 30 秒，不自动重试。
- **正常**：模型正常结束并返回了非空文本，这一行会显示 **模型回复** 和模型的原话。它不一定照抄 `ok`，回一句别的也算正常。
- **失败**：请求失败、超时、空响应或未正常结束；展开可以看到错误与已收到的部分文本。
- **首次响应** 指适配器收到 HTTP 响应头的时间，不是第一个 Token，也不是总耗时；观测不到时显示 **无法测量**。
- 结果只留在当前页面，刷新或离开就清空；离开页面会取消还没发出的检查。用量作为 `doctor` 诊断记录进入审计。

供应商或模型刚改过却还没应用时，健康检查会直接拒绝（提示先应用连接或模型定义），避免测的不是运行中的那一份。

## 7. 常见问题

- **新建供应商后拿不到模型列表**：密钥错了、地址少了 `/v1`、或者服务要求自定义请求头。先用 **手动添加** 试一个已知存在的模型 ID，能把问题缩小到连接还是目录。
- **模型加进来了但 Bot 不回复**：先看 **模型** 页的主模型是否已保存，再点 **测试**。健康检查失败时不要猜模型名，按错误信息检查供应商返回。
- **换了模型后行为变了**：不同模型的工具调用与指令遵循差别很大，尤其是思考强度与上下文长度。回到[你的第一个人设](first-persona.md)重新试几场，比反复改 Prompt 更省时间。
