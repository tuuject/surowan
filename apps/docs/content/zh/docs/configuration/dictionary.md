# 辞典配置

`dictionary` 段只有一个字段：自动注入模式。它决定每一批消息把哪些辞典词条放进上下文。词条本身（主词、别名、解释、全局或群组作用域）存在数据库里，用面板「辞典」页、MCP 或 HTTP 接口维护，不写在配置文件中。

## 什么时候有影响

辞典只对 Telegram 生效，而且只对配置里列出的 Chat 生效。没配置的群不会注入，也拿不到查询词条的工具。

私聊群与群组看到的范围不同：私聊只能读全局词条，群组读「全局 + 本群」的词条，永远不会读到别的群的词条。

## 注入模式

| 值 | 行为 |
| --- | --- |
| `off` | 不自动注入。模型仍可以主动调用查询工具查词条。 |
| `on_demand` | 本批消息的正文里出现某个主词或别名时，注入对应词条。这是**没有写这段配置时的默认行为**。 |
| `aggressive` | 把当前作用域的有效辞典整本预加载进上下文，减少模型查工具的次数。 |

面板上的对应叫法是「关闭 / 按需 / 预加载」。

匹配是逐字包含，不是分词：一段文本里出现主词或别名就算命中，另外容忍中英文之间那种排版空格（`AB 钙` 与 `AB钙` 视为相同）。大小写和词序都保持原样。

## 覆盖关系

优先级从高到低：

1. `telegram.chats[].dictionary_injection_mode`（该群自己的覆盖）
2. `dictionary.injection_mode`（全局）
3. `on_demand`（产品默认）

所以三者都可以不写，行为和显式写 `on_demand` 一样。

```jsonc
{
  "dictionary": {
    "injection_mode": "aggressive"
  },
  "telegram": {
    "chats": [
      {
        "id": -1001234567890,
        "dictionary_injection_mode": "off"
      }
    ]
  }
}
```

这段配置的效果是：所有群默认预加载，只有 `-1001234567890` 这个群关掉自动注入。要清掉某个群的覆盖，删掉那个字段即可，它会重新继承全局值。

## 注入到上下文的形状

无论哪种模式，注入内容都是：

- 一个带 `<untrusted_dictionary>` 标签的独立块，位置在 Sticker 目录与历史消息之间；
- 每条词条一行，带自己的 ID 与修订号；
- 内容按剩余预算裁剪：本批新消息优先，放不下的词条被丢掉；
- **去重跟着上下文走**：检索时如果保留的历史里已经带着同一「ID + 修订号」的标签，就不再注入。上下文 GC 丢掉那一批之后，词条会重新可注入；词条被改过则修订号变化，下一批自动刷新。

块里的内容是数据，不是指令；词条由人写，不授予任何权限。

## 生效方式

`dictionary.injection_mode` 与 `telegram.chats[].dictionary_injection_mode` 都是热更新，改完下一次应用就对下一批消息生效，不需要重启。切换模式不会中断正在进行的 Invocation：注入是每批消息进上下文时算的。

## 示例（全局单值）

```jsonc
{
  "dictionary": {
    "injection_mode": "on_demand"
  }
}
```
