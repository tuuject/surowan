# Surowan product knowledge

Sources below are paths in the manual document space.

## Identity and commands

- 塑料碗 / Surowan is a self-hosted Agent bot for Telegram private chats, groups, Supergroups and Forum Topics; without Telegram it still runs Admin Panel and Playground rooms. Only allowed Chats/Topics are processed; triggers do not guarantee replies. [Setup](guides/installation.md), [Telegram](guides/first-bot.md), [Playground](guides/playground.md), [Chat boundaries](guides/chats.md)
- Intent “别理我 / 不要回复我 / 忽略我的消息 / ignore me” → /ignoreme; “恢复接收 / 重新理我 / 取消忽略 / unignore me” → /unignoreme (intent labels, not natural-language aliases). Commands edit the sender's ignored_user_ids; /unignoreme works while ignored. Any personal-account member in an allowed Chat/Topic can use them, no admin or anonymous identity; optional @Bot名 targets the bot. Persisted in config.jsonc and applied across this Chat's Topics only; existing messages/Context and audit remain, and apply failure keeps the old running config. [Self-ignore](developer/telegram-commands.md)
- /whoami returns a member's Telegram numeric user ID. Configured telegram.admins may use /pause, /resume, /model, /cut_topic, /rebuild_context, /allowlist. /rebuild_context discards the current topic's continuous Context without truncating chat history. /allowlist adds the current Chat immediately; only this command works outside the allowlist, and non-admin requests are silently ignored. Other admin commands lack complete argument syntax in the manual. [Commands](developer/telegram-commands.md)
- /model can trigger configuration reload. /status shows the effective Chat model (access level undocumented). [Prompt application](guides/first-persona.md), [Chat models](guides/chats.md)

## Capabilities and boundaries

- /ask explicitly invokes with this message, including for /ignoreme members; anonymous chat identities can ask, other bots cannot. Prefix stays in history; no guaranteed reply. [Ask](guides/chats.md)
- Participation: active hours, direct @, replies to the bot or keywords trigger group runs. Chat hours replace global; keywords append. ask_only (global or per Chat; false opts out) allows only /ask, zero collection time, no attention; ordinary messages remain stored/remembered, ignored members other messages stay dropped. Normal /ask behaves like @. Attention windows are per Chat+Topic; private chats bypass it. Blocked messages may appear later as history; edits do not trigger; standalone stickers need sticker_trigger_enabled. [Participation](guides/chats.md)
- Entry gate (telegram.decision_gate, off by default; group Chats can override): a small decision model answers one yes/no question before a due group batch starts an Agent run. shadow only records; enforce closes rejected batches as skipped_budget/decision_gate_dropped, messages stay as history. /ask, direct @, replies to the bot, keywords, private chats, Playground, task receipts and recurring alarms bypass it. Any request or key failure admits the batch, so a broken key silently disables it; run doctor after enabling. Enforce skips that Chat's proactive sampling; decision cost is outside the daily budget. Hot applies; Admin → Entry gate, per Chat in Chats. [Entry gate](guides/tuning.md)
- Models must be explicitly configured. Agent needs text input; direct image understanding and Vision need image input. Chat provider+model override together, thinking can override alone; Topics share Chat settings. [Models/Tool Model](guides/models.md), [Chat overrides](guides/chats.md)
- Personality: global agent.system_prompt_file plus Chat instructions_file; paths relative to config.jsonc. Topics share Chat instructions. Prompt changes rebuild affected Context next run; they grant no permissions. [Personality](guides/first-persona.md)
- Memo Pad: Chat-scoped durable notes shared by that Chat's Topics; each has a summary and a Markdown detail, optional expiry (short-term) or permanent (long-term). Only short-term summaries are injected; long-term entries are found with search_memory. Chat-owned images are stored as pwblob:// blobs. Admin panel manages entries. [Memory](guides/knowledge.md), [Context limits](guides/tuning.md)
- Dictionary: global and current-group terms/aliases; Topics share group terms, private chats read global only. Agent edits its group's terms, not global/other groups. Literal case-sensitive matching, not semantic search. Off/On Demand/Aggressive injection; CSV/JSONL and reviewed AI merges in Dictionary panel. [Dictionary](guides/knowledge.md)
- Images: understanding differs from optional generation. With image configured, generation and reference edits use current-conversation refs. Admin has settings/workbench/history/assets; enable/disable hot applies; delivery/uncertain-send protections apply. [Generation](guides/images.md), [Vision](guides/troubleshooting.md)
- Alarm: alarm/list_alarm/delete_alarm create/manage persistent reminders; receipts let Agent decide whether to follow up, not auto-send prewritten text. web_fetch reads simple HTTP(S) pages, keeps their image links and can open JPEG/PNG/WebP images (optional referer) for image-capable models, without login/Cookies/auth headers or JS rendering; complex access needs MCP. [Extensions](guides/tools.md)
- Read-only System Skills do not grant permissions. MCP exposes configured external tools under policies; Admin → MCP servers manages servers and per-Chat bindings and applies them hot (stdio connection fields stay in config.jsonc). Bundled manuals are readable on demand; no user document spaces or plugin marketplace. [Extensions/manuals](guides/tools.md)
- Budgets: Agent daily Token cap is global (Chats/Topics, chat read_image); background sticker Vision has separate limits. Not a money cap. Budget sleep skips new runs; Wake now does not replay them. Alarm receipts have a narrow sleep/daily-budget exemption, still subject to other gates. [Budgets](guides/tuning.md)
- Sending: default one explicit reply per target; exact duplicate text/stickers and the previous content re-aimed at another target are also blocked within a run. agent.allow_reply_message_multiple_times and agent.send_duplicate_guard_enabled control separate guards; neither removes image uncertain-delivery protection. [Sending settings](guides/tuning.md)

## Configuration and operations routes

- No file watcher: saving a file alone does not apply it. Settings → Apply config file; Prompts, Models, Providers, Chats and Harness tuning edit related settings. New Chat/model/Prompt/Agent/MCP changes can hot apply; deleted Chats, Topic ranges, Admin/path changes require restart. Saved and Running may differ. The admin section is required (enabled defaults true); Telegram is optional and a missing token is the disabled state. [Config lifecycle](configuration/lifecycle.md), [Admin](guides/admin.md)
- Admin audits messages, invocations, contexts and usage. Passkeys need public_url. API keys allow restricted inspection/replay, not config edits. Replay uses current config, calls a paid model, sends no Telegram messages; not full historical restoration. [Admin](guides/admin.md)
- Secrets live in the keychain (key.json) as named entries; config references them by name. The panel Keychain page lists entries with their use sites, creates, rotates in place (all uses take effect on next apply), deletes unused entries and purges orphans; values are never shown. env/command refs are read-only in the panel. Secret input fields accept a new key or an existing entry. [Keychain](guides/admin.md)
- Service CLI: serve, check-config (offline), doctor (real dependency probes, possible model cost; Telegram probe skipped without a token), backup, configure (existing config + TTY). admin-account creates the sole admin or resets its username/password after stopping the bot; it always revokes sessions and keeps passkeys unless --revoke-passkeys. surowan-utils is a separate Admin API client: login/doctor, config show, prompt get, models list and invocation list/get/prompts/preflight/media/replay. [CLI](developer/service-cli.md), [Recovery](guides/admin.md)
- Setup and upgrades: [Quick start](guides/installation.md) (Telegram optional; Playground trial), [Host/Docker requirements](guides/installation.md), [Agent-assisted deployment](guides/agent-assisted.md), [Upgrade](guides/maintenance.md). [Backup/restore](guides/maintenance.md): no restore command; config/Prompt/secrets need separate backups. [No reply/startup failure](guides/troubleshooting.md): check delivery, allowlist, Bucket, participation/pause/budget, then invocation audit; silence can be intentional.
- Exact configuration: [Semantics](configuration/lifecycle.md), [Fields](configuration/fields.md), [Complete example](examples/config.example.jsonc.md), [Prompt example](examples/system-prompt.example.md), [Compose](examples/docker-compose.yml.md).
