# Surowan product knowledge

Sources below are paths in the manual document space.

## Identity and commands

- 塑料碗 / Surowan is a self-hosted, persona-agnostic Harness server. Telegram is the only real platform today; without a token the Admin Panel and Playground rooms still run, and only allowlisted Chats/Topics are processed. [Start](guides/index.md), [Telegram](guides/first-bot.md), [Playground](guides/playground.md), [Chats](guides/chats.md)
- Bot commands by tier: `telegram.admins` (`/pause`, `/resume`, `/model`, `/effort`, `/cut_topic`, `/rebuild_context`, `/allowlist`), identifiable members (`/whoami`, `/ignoreme`, `/unignoreme`), anyone (`/ask`, `/help`, `/status`). Group owners and Telegram admins get nothing extra; replies are deterministic, skip the model and are not chat history. Only `/allowlist` runs outside the allowlist. [Commands](developer/telegram-commands.md)
- Self-ignore intents “别理我 / 不要回复我 / 忽略我的消息 / ignore me” → `/ignoreme`; “恢复接收 / 重新理我 / 取消忽略 / unignore me” → `/unignoreme` (intent labels, not aliases). They edit only the sender's `ignored_user_ids` across this Chat's Topics, persist to `config.jsonc`, and a failed apply keeps the old config.
- `/ask <question>` wakes the bot for that one message, including ignored members and anonymous admins; no reply is guaranteed. `/help` lists the sender's commands; `/status` shows model, effort and tokens.

## Capabilities and boundaries

- Participation: active hours, direct @, replies to the bot and keywords open a group batch; a hit outside the hours opens an attention window (per Chat+Topic). Chat hours replace the global list, keywords append. `ask_only` (global or per Chat, `false` opts out) leaves `/ask` as the only entry, with a zero-second batch and no attention window, while ordinary messages are still stored and remembered. Private chats bypass it; edits never trigger; a lone sticker needs `sticker_trigger_enabled`. [Chats](guides/chats.md)
- Entry gate (`telegram.decision_gate`, off by default, Chat overrides): a small decision model answers one yes/no question before a due group batch starts a run. `shadow` only records; `enforce` closes rejected batches as `skipped_budget`/`decision_gate_dropped` and keeps the messages as history. Bypassed by direct triggers, private chats, Playground, receipts, recurring alarms, resumes, catch-up and `/ask`-only chats. Request or key failures admit the batch, so run `doctor` after enabling; enforce also stops proactive sampling, and its cost stays outside the daily budget. Hot; panel **Entry gate**. [Tuning](guides/tuning.md)
- Models: the Agent role needs text input; direct image understanding and the Vision role need image input. Per Chat, `provider`+`model` override together and `thinking_level` alone; Topics follow their Chat, and a model switch stops runs on the old model. Nicknames change only how `/status`, `/model` and `/effort` show a model. [Models](guides/models.md)
- Personality: global `agent.system_prompt_file` plus per-Chat `instructions_file`, paths relative to `config.jsonc`, Topics sharing the Chat layer. Prompt changes rebuild affected Context next run and grant nothing. [Persona](guides/first-persona.md)
- Memo Pad: Chat-scoped notes shared by its Topics, each a summary, a Markdown detail and an optional expiry. Short-term entries are injected; long-term ones are found with `search_memory`. Chat-owned images become `pwblob://` blobs. [Memory](guides/knowledge.md)
- Group memory (per Chat, off by default): a sleeping pass turns quiet or finished local days into event summaries with message-id ranges; `search_group_memory` then `read_group_messages` recall them. `thirty_hour_clock` shifts dated searches only; raw messages survive `online_days`. [Memory](guides/knowledge.md)
- Dictionary: global and current-group terms and aliases; Topics share the group's, private chats read global only, and the model edits only its own group's entries. Literal case-sensitive matching, `off`/`on_demand`/`aggressive` injection, CSV/JSONL import, reviewed AI merges. [Memory](guides/knowledge.md)
- Images: understanding differs from optional generation. With `image` configured the panel gains the workbench, records and the asset library; an asset becomes Agent-visible one by one (matched by text), and AI extraction only fills the form, for a billed tool-model call. [Images](guides/images.md), [Vision](configuration/vision.md)
- Alarm: `alarm`, `list_alarm` and `delete_alarm` manage one-off reminders; a due alarm injects a receipt and the model decides whether to follow up. Recurring alarms are admin schedules (rules or 5-field cron, own time zone, Run now, next-run preview) whose trusted `<admin_scheduled_task>` prompt skips the daily budget and sleep. `web_fetch` keeps page image links and opens JPEG/PNG/WebP up to 20 MiB (optional `referer`) for image-capable models; no login, cookies or JS. [Tools](guides/tools.md)
- Outbound MCP: servers are admin-configured (stdio only in `config.jsonc`), connect in the background and degrade alone. `exposure: progressive` hides tools behind the single `mcp` search/help/call primitive, `skills` exposes verified `mcp-skill://` documents to `read`, and per-Chat bindings only narrow. [Tools](guides/tools.md), [MCP](configuration/mcp.md)
- System Skills are read-only Markdown under `system:///skills/`; the model reads them with `read` and calls internal capabilities with `execute`. No Skill upload, marketplace or third-party IM host. [Extensions](developer/extensions.md)
- Budgets: `agent.daily_budget.max_tokens` is a global token ceiling for Chats and in-chat `read_image`; background Vision has its own limits and decision requests stay outside. A breaker, not a money cap. Budget sleep closes new batches without replay; alarm and recurring-alarm receipts are exempt. [Budgets](guides/tuning.md)
- Sending: one explicit reply per target by default, and within a run identical text or stickers and the previous content re-aimed elsewhere are blocked. `agent.allow_reply_message_multiple_times` and `agent.send_duplicate_guard_enabled` are separate guards; neither removes the image uncertain-delivery protection. [Sending](configuration/agent.md)

## Configuration and operations routes

- No file watcher: saving alone never applies; use **Settings → Apply config file** or any panel save. Hot: adding **and removing** a Chat (removal stops its runs and keeps the data), prompts, models, agents, MCP, the gate, batch timing, `retention.online_days`, rotating a Keychain entry in place. Restart: a Chat's `topic_ids` and `timezone`, `admin.*`, `data_dir`/`paths`, `web_fetch`, `process_bot_messages`, most `vision` limits. The `admin` section is required (`enabled` defaults to true); Telegram is optional, and a missing token is the disabled state. [Lifecycle](configuration/lifecycle.md), [Admin](guides/admin.md)
- Deleting a Chat differs from removing it from the file: the panel delete stops its runs, then deletes its memories, images and stored messages, and may answer `chat_delete_pending` or `chat_still_authorized`, keeping the data. [Chats](guides/chats.md)
- Admin Panel: audits messages, Invocations, Contexts and usage, plus Playground rooms. No web sign-up: the first administrator comes from `pairing create --web` (creating a password-less `admin`) or the offline `admin-account`, which needs the service stopped, revokes sessions and keeps passkeys unless `--revoke-passkeys`. Passkeys need `admin.public_url`. [Admin](guides/admin.md)
- API keys have four modes — `read`, `read_write`, `read_paid`, `all` — and a key may do whatever its mode allows, including configuration, Chat and prompt writes for `read_write`/`all`; replay and Resume also need paid. Account, passkey, API-key and Keychain management, plus `/api/live/*`, stay panel-session only. Paired clients have the same modes. [HTTP](developer/http/index.md), [Agent access](guides/agent-assisted.md)
- Secrets live in the Keychain (`key.json`) as named entries the config refers to by name. The panel lists use sites, creates, rotates in place (all uses pick it up on the next apply), deletes unused entries and purges orphans; values are never shown, and `env`/`command` refs are read-only. [Admin](guides/admin.md)
- Service CLI: `serve`, `check-config` (offline), `doctor` (real probes, model cost, Telegram skipped without a token), `backup`, `configure` (needs a TTY), `admin-account`, and `pairing`/`clients`, which run alongside `serve`. The client CLI `surowan-utils` has `auth init/pair/status/permissions/logout`, `doctor`, `login`, `config show`, `prompt get`, `models list`, `invocation list/get/prompts/preflight/media/replay` and one command per panel route. [Server CLI](developer/service-cli.md), [Client CLI](developer/client-cli.md)
- Setup and recovery: [Install](guides/installation.md) (Telegram optional, Playground trial, host or Docker), [Agent-assisted tuning](guides/agent-assisted.md), [Upgrade and backup/restore](guides/maintenance.md) (no restore command; config, prompts and `key.json` need their own backups), [Silence and startup failures](guides/troubleshooting.md) (delivery, allowlist, batch, participation/pause/budget, then the tool session; silence can be intentional).
- Exact configuration: [Semantics](configuration/lifecycle.md), [Fields](configuration/fields.md), [Complete example](examples/config.example.jsonc.md), [Minimal example](examples/config.minimal.example.jsonc.md), [Prompt example](examples/system-prompt.example.md), [Compose](examples/docker-compose.yml.md).
